# 訂位與候位：目前的開發版本

目標是所有店家免費使用，讓訂位、點餐、會員與營運資料共用，並能帶走自己的資料。現在不能宣稱已超越 inline 或完成整套會員服務。

## 店員怎麼用

1. 老闆進入「訂位與候位 → 訂位設定」，照實際桌位填可坐人數，確認用餐時間、清桌時間及營業時段後儲存。
2. 店員選日期、人數、時間，填客人姓名及聯絡方式，按「確認訂位」。系統自動安排最小的合適桌位；只會使用老闆明確允許的併桌組合。
3. 客人來了按「客人到了 → 安排入座 → 開始點餐」。餐點選項與一般品項沿用正式接單，桌號、原料與廚房單一起保存，可明確選擇既有會員。備餐、收款及交付後按「回到這一桌」。
4. 沒有空桌時可以候位。候位不代表已保留桌位，「有位了，安排桌位」會重新核對容量。
5. 接待卡直接顯示實際待收金額。尚未結清時按離席會先提醒；客人確實離開也能保留未收款，餐點單與庫存不會被刪除。已離席未結清的餐點繼續顯示，也可按「桌餐點待結清」找其他日期的未收款。

可從 CRM 工作區、搜尋或功能選單進入。配對手機與店面電腦使用同一個保存權威；獨立瀏覽器的本機模式有自己的資料，不會自動與電腦合併。

## 客人怎麼用網站訂位

1. 老闆確認桌位、線上可用桌及時段，按「開放網站訂位」，把顯示的 `/reserve/` 網址給客人。
2. 客人不用登入：選人數、日期與空閒時間，填姓名電話，按「確認訂位」。網站直接使用店面電腦同一份訂位與桌位資料；保存成功後，電腦及配對手機會收到。
3. 保存私人訂位連結，可查自己的最新狀態、改時間或取消。連結的權杖在網址片段與授權標頭中，不放在查詢參數或伺服器訂位紀錄中。店家暫停新接單後，客人仍可查回及取消尚未開始的訂位。

啟用私人連結保護後，連結預設在訂位結束後七天到期。老闆可停用或重發連結；停用不會取消桌位。重發保留訂位，舊連結失效，新連結顯示自己的到期日；到期後重發至少保留七天供客人核對。網址狀態會更新，避免複製已停止服務的舊網址。

目前網址若顯示店內 IP，只能在店內網路使用。既有的對外連線啟用後可顯示網際網路網址；電腦及網站服務需要保持運作。本次開發沒有啟動真實商家對外連線、佈署公開網站或購買固定網址。自有網域、長期穩定的對外服務與實際外網驗收仍需後續完成。

網站會先保存原請求編號及私人權杖，再送出。回應中斷或重新開啟時，使用原編號確認，避免重複訂位。無法保存原編號時不送出。額滿、店面設定更新及過期的改期操作必須重新確認；客人不能設定桌位、報到、入座或查看其他人的名單。

## 保存與還原

`pos-reservation/v1` 的每個操作使用唯一原編號、店面與還原世代、整本版本及被變更訂位的版本。相同原編號與內容重試只讀回原保存結果。更改內容不得沿用已保存編號。

桌位以實際桌號識別，能沿用既有點餐桌號。訂位先建立桌位時，產生點餐桌碼會採用同一組桌號。不能刪除仍有未來訂位的桌號，也不能讓同一張桌同時入座兩組客人。時間使用店面 IANA 時區，重複或不存在的夏令時間不接單。

店員訂位使用備份格式 **15**；開放網站或使用網站訂位後為 **16**；啟用私人連結保護、重發連結或從訂位建立餐飲單後為 **17**。較舊程式不能繼續修改不支援的店面。完整備份可攜帶本機復原保護索引，保留原訂位與餐飲承諾。未帶出到另一台裝置的紀錄，不能憑空重建。

M19 的訂金後端開發使用格式 **18**，已接政策版本、明確核對的金額、現金／銀行原收款、來源退款與既有會計預收款；詳細規格見 [訂位訂金與餐點抵款](RESERVATION_DEPOSITS_SPEC.md)。餐點自動抵款、店主條件畫面與客人確認流程仍須一起完成，所以目前未開放店家的訂金收款入口。不能把後端測試當成整個訂金功能已可營業。

還原較舊備份後，已知訂位會顯示並暫停新接單。只有訂位紀錄缺少時，老闆可核對後找回原紀錄；若缺少已接單的餐點、原料或款項，畫面會標示「待找回」，引導老闆預覽並確認完整備份復原，不重建餐飲單或再扣庫存。找回前，一般接單、POS、儲值等新的庫存與款項異動也會暫停；查詢、原單核對與老闆的完整復原仍可使用。仍被復原紀錄中的餐飲單引用的會員也不能從一般刪除入口移除。

## 尚未完成的完整情境

免登入網站、訪客自助改期、取消與原單查回已有開發實作及隔離店面測試。訂位訂金與退訂對帳、自動通知、跨店報表、與點餐及 CRM 的完整接續、實體手機及真實店員首次使用驗收仍未完成。點數、兌換券與商家自訂會員福利仍是必要工作，沒有因這個檢查點完成而被移出範圍。

功能比較只採用 inline 公開說明：https://inline.app/zh/features 、https://inline.app/zh/flexible_deposit 。inline 已提供訂候位、桌位控管、訂金與 CRM。超越與否還需要相同情境的可靠性、完成率、操作時間及真實店員驗收；通過單元測試不能取代這些證據。
