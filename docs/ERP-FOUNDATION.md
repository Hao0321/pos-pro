# 免費 ERP 基礎：採購到付款

本階段把現有 POS 擴充為可實際核對的採購流程；所有功能免費。Oracle 與 Odoo 的公開流程文件只作能力參考，沒有移入其程式，也不宣稱已達成全面產品或合規認證。

## P1. 單一資料權威

桌面 SQLite、已配對手機的 HTTPS 連線、獨立瀏覽器，各自沿用既有交易權威。手機連線到同一間店時使用桌面資料庫。每次操作先保存原操作編號；回覆遺失沿用原編號，已提交紀錄與庫存不可重複。

## P2. 新採購完整流程

1. 建立採購單：凍結供應商、品項、訂購量與單價，數量最多三位小數、單價最多兩位小數。
2. 分批收貨：總實收不得超過訂購量；在同一交易寫入庫存、目錄連結、收貨單與操作回執。
3. 登錄供應商請款：逐行核對採購、已收貨與未請款數量；供應商單號不可重複，可分次請款並設定到期日。此為內部請款憑證，不是電子發票開立或稅務申報。
4. 分次付款：只付已請款未付餘額；銀行付款與現金付款分開記錄。現金必須連結開啟中的班次，並同時建立現金支出。記錄付款不會呼叫銀行或支付商。
5. 付款更正：以附理由的完整反向紀錄沖銷，保留原付款。現金沖銷列入當次開啟班次的現金收入。
6. 未收貨採購可取消；已有收貨、請款或付款的文件保留，不可直接修改或刪除。

## P3. 帳務與精度

- 收貨：借存貨 1211、貸進貨暫估應付 2102。
- 請款：借進貨暫估應付 2102、貸應付帳款 2101。
- 付款：借應付帳款 2101、貸現金 1101／銀行存款 1103；沖銷方向相反。
- 金額以整數分、數量以千分單位計算。分批金額使用累計差額，避免不同拆分方式產生尾差。每筆分錄借貸平衡，歷史單價不隨商品成本更新而改變。
- 收貨、請款與付款狀態各自計算，部分付款不阻止繼續收貨。
- 採購憑證依凍結的採購單價入帳。現有銷貨成本仍使用商品成本及成交快照；本階段未改成 FIFO／移動平均，也未自動建立期初庫存分錄。存貨評價與原有手動帳仍須核對，不宣稱完整財務結帳能力。

## P4. 升級、備份與歷史

新增資料存於採購單的版本化 `procurement` 欄位，完整 JSON 備份包含收貨、請款、付款、沖銷與回執。舊單維持歷史模式，不自動重建分錄或推測付款；新建採購才使用新流程。舊雲端快照若不能完整保留新資料，必須明確拒絕，不能靜默遺失。

## P5. 驗收門檻

以相同輸入驗證：分批／小數收貨、分次請款與付款、過收／超請／超付拒絕、同供應商重複單號、狀態過期、權限、回覆遺失後原編號重試、交易後段失敗完整回滾、重新啟動、完整備份還原，以及真實介面至 SQLite 和配對手機的流程。舊收銀、退款、班次、餐飲、庫存與手機共用回歸必須維持通過。

## 後續能力與目前界線

本階段沒有宣稱完成多公司／多幣別、正式稅務及電子發票、會計關帳、採購退貨、預付貨款、跨倉、批號效期／FEFO、FIFO 成本、完整生產排程或人資薪資。餐飲原料與成本將在這個可追溯基礎上逐步擴充。全功能免費不等於所有第三方服務或硬體成本由本專案負擔。
