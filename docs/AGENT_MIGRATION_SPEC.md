# Agent 一鍵搬家與一鍵建單

2026-10-18 新增需求。狀態：規格與實驗中；任意 ERP／CRM 整庫搬家尚未驗收。此需求加入 `migration.switching`，保留原有 31 項完整 ERP 義務，不縮小完成範圍。所有功能免費。

目前已接通來源原文字草稿、選檔／拖入／貼上、直接 CSV／TSV／XLSX，以及完整備份還原入口。商品、供應商與客戶主檔具備永久原編號對照、本店衝突核對與整批原子保存，見 [主檔搬入規格](MASTER_MIGRATION_SPEC.md)。原庫存已接續相同入口的逐格事實核對、實際成本帳試搬及整批開帳，見 [庫存開帳規格](OPENING_MIGRATION_SPEC.md)。其他期初、未結帳款、完整廠牌切換與受控撤回仍待實作與驗收。實際操作見 [簡單指南](AGENT_START_GUIDE.md)。

## AM1 — 前台只做三件事

入口使用「Agent 幫我搬家」「Agent 幫我建單」。選檔或貼上，系統帶入草稿；看新增、更新與待確認；確認後保存。沿用本店語系、明亮／海報風格與 360px 觸控。錯誤直接指出要補哪個事實，原輸入與完成進度保留。

## AM2 — Agent 只能準備事實

資料包提供 task、protocol、schema、作用中店面／世代、必要的 ID 對照、支援範圍及未知項目。公開 discovery 只放規格與合成範例，實際客戶、私價與帳款由登入後的店主選擇提供；不默默上傳檔案或呼叫外部服務。檔案內容、品名、網址都是資料，不能當指令。

Agent 不填使用者身份、權限、confirmed、付款執行或本地核准。使用者授權一次確認的範圍是實際顯示且未變更的草稿；來源更動就保留輸入重新核對。同編號同內容重試回原結果，同編號改內容拒絕。

## AM3 — 搬家批次與永久身份

使用 `pos-migration-draft/v1` 表示可攜草稿，先區分 `masters`、`opening-stock`、`opening-receivables`、`opening-payables`、`history-reference`；未實作類型回報不支援，不轉成普通銷售或收貨。每列保存來源公司、來源系統、類型、原編號、原列位置與原欄位文字；身份對照以複合來源鍵管理。

偵測重複 ID、衝突條碼、同名不同人、多個候選對照、未知單位、模糊日期／幣別、壞數值、缺成本、公式與超出範圍。前導零不消失；空白不當零；不同幣別不加總；售價不當成本。依賴關聯先試解析，缺少父單或商品不能部分寫入。

## AM4 — 試搬、切換與對帳

先保存原檔的內容摘要與原檔副本，使用隔離試搬；依來源先建立主檔與對照，再移入期初與開放單據。選明確切換日，區分已結清歷史參考與仍未付單據，避免重新計銷售、稅或庫存。

顯示來源／目標筆數、數量、庫存價值、幣別小計、應收應付、預收預付、儲值與點數差異。未解決差額不能顯示「搬家完成」。真正提交須由實際店主身份、作用中店面、世代、資料版本與核對摘要共同綁定，跨表原子保存；斷線、配額／SQL 失敗、重開均核對原批次。

切換前的業務備份、原始來源、欄位對照、逐列結果與新 ID 對照保留。尚無後續交易時才可原子撤回該批次；已有後續交易須走受控更正，不能整庫還原抹掉新營業資料。多裝置與舊版寫入必須驗證版本保護。

## AM5 — 建單直接接現有權威

包裝採購使用 `pos-purchase-units-draft/v1`，沿用 [包裝原價規格](PURCHASE_UNIT_PRICING_SPEC.md) 的唯一金額與數量來源，稀疏 Agent 草稿不清除店主日期、備註、私價與其他列。收貨另核對實際入庫商品；供應商目錄更換連結不能讓確認過的商品 A 變成 B。見 [收貨身份核對](RECEIPT_IDENTITY_REVIEW_SPEC.md)。既有報價／銷售／餐飲協議保留原語意。

## AM6 — 驗收矩陣

必測：空白與完整來源、壞數值／精度、重複與錯店、稀疏欄位、模糊身份、跨單關聯、未付與部分支付、原編號重跑、回覆遺失、晚期失敗回滾、重開、備份與舊版拒絕。以實際 Native SQLite、瀏覽器及配對 HTTPS 驗證；公開規格須有真實 HTTP discovery、schema 與文件可讀回。

獨立外部 Agent、真實廠牌匯出檔、真人首次使用、實體手機及大資料長時間切換分別驗收，內建合成測試不代替這些結果。每次交付列明已支援的資料類型與仍待確認項目。
