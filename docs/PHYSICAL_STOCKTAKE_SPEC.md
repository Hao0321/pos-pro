# 實際盤點與 Agent 數量草稿

實作中、尚未交付。補充 [庫存 I1–I12](INVENTORY_COST_SPEC.md)，保留原始 31 項 ERP、成本試算、報表與完整備份門檻。前輪 `288ab7c` 是已驗證的進展；本輪只更新開發來源，不改已交付的 2.16.0 安裝檔，不因局部測試宣稱完整 ERP 或真人驗收完成。

## P1 數架上的貨，分清預留和製作

預設盤點代表「仍在架上、尚未投入製作的原料／商品」，包含已替客人留著但尚未開始製作的份數。系統可用量與這個實體數量不同。權威端從原預訂分配帶出「尚未製作的預留」，不論已收款或未收款；已開始的製作、已完成交付、取消後耗損不再算架上。取消且未製作而已釋放的原料已在可用量，不重複相加。

`預期架上量 = 可用量 + 未製作預留量`，`新可用量 = 實際架上量 − 未製作預留量`。製作中／待交付數量另列供核對，不讓使用者再扣一次。實際數少於不能任意侵占的預留時，保留輸入，要求核對原預訂，不能產生負可用量或偷偷取消客單。已付款但未製作也適用。商品配方、舊單的固定分配、數量與單位沿用原紀錄。

## P2 精確的輸入和權威快照

所有數量用千分之一基本單位整數計算，支援零、最多三位小數與明確上限。空白表示未盤；負數、非數、過度精度、無限值、超範圍不能被截斷、夾成零或部分保存。權威端回傳店面、還原世代與每品項的固定核對指紋，綁商品身份／單位／可用量及相關預訂的原版本、數量、付款與製作狀態。確認時重算，不信任客端計算出的可用量。預訂開始製作即使沒有改可用庫存，也使舊核對失效。

## P3 明確的版本化盤點

新盤點固定使用 `pos-physical-stocktake/v1` 與 `physical-shelf`，帶權威 context、實際數量及原指紋；禁止客端塞入可用量、角色、憑證或過帳指令。已知舊 `available` 內部流程保留其原語意，未知數量語意拒絕。有活躍預留時，舊介面模糊盤點不能默默當可用量寫入。全部已盤品項都核對，包括差異為零者；未盤品項保持原樣，不以顯示、搜尋或分頁上限遺漏。

## P4 一次保存業務、成本及原回執

原生 SQLite 和獨立瀏覽器每次盤點在同一原子提交保存新可用量、原操作、凍結盤點結果、成本事件及回執。盤虧只轉出可用庫存，不能動到別人的預留。盤盈的新增來源預設成本待確認，不拿商品參考價冒充已知實際成本、不產生虛構現金；原已知零與未知成本分開。未啟用成本帳的盤盈也保留未知依據；日後開帳時，無法證明仍有多少未知來源的該商品及其預留均先待確認，需明確確認總成本才可估值。舊可用量盤點的歷史事件保持原樣。

每次只有一個正式原編號。重送先回原結果，再檢查目前資料時效；已還原移除的原編號仍須找回原紀錄。回執保留當時的架上數、原可用／預留／製作、差異、新可用量、原商品身份與指紋；再次查詢不改寫這份當時結果。回覆損壞、遺失、容量不足或晚期失敗，不重建第二筆盤點。

## P5 瀏覽器的成本寫入不能靠旁路

獨立瀏覽器的新盤點必須由共用規則產生、重播並核對完整成本追加，原事件前綴不變；全部業務變更須等於權威計畫。不能用一般 `allow`、清空成本陣列或寬鬆覆寫繞過原柵欄。其他尚未接成本帳的瀏覽器交易繼續拒絕，不能據此宣稱全庫存里程碑完成。配對手機一律使用原生同一間店，不建立另一份離線庫存。

## P6 少字、大按鈕、草稿不丟

「填實際數量 → 看差異 → 確認保存」。先看品名、單位與大輸入框，預留／製作細節需要時展開。錯誤直接給下一步；不以自動填入系統預期數冒充實盤。搜尋、分頁、掃碼＋一均沿用同一份草稿；掃碼是實際架上數加一，需保持三位小數與範圍。草稿依店面及目前帳號隔離，離頁／重啟保留原內容與核對指紋。資料變動時保留原數，要求逐項重新核對，不靜默接受新指紋。

不確定結果時鎖住同份草稿、沿用原編號查詢；核對完成接回原頁。成功頁及 CSV 使用正式回執的凍結前後值，不能用已更新的商品庫存重算而把差異變成零。四語、明亮／海報、360px、大字與鍵盤均保持完整；真人長者／兒童及母語者驗收另列。

## P7 Agent 只填數量

一次複製最小資料包：版本、店面／世代／核對指紋與品項 ID、名稱、基本單位。回覆只允許同 context 的 `{id, quantity, unit}` 明細，不含售價、成本、權限、確認或執行命令。每個數必須來自實際盤點資料，沒有的留白，不能以預期量代填。使用者貼上就能看原數與差異，明確確認後才保存。錯店、過期 context、重複／未知品項、未知欄位、過量、模糊單位與非有限數一次拒絕並保留草稿及原文；不部分套用。先核對原始數字字面值，再接受解析後的數值；新盤點僅接受一般十進位、最多三位小數，不讓極小非零值經 JSON 解析後被當作 0。

## P8 不改歷史與備份

新盤點的凍結回執與成本證據一起進完整備份、保護來源及原編號找回，逐筆重播並核對原審核紀錄。標為已啟用成本帳的盤點，即使零差異，也必須仍有對應成本事件，不能用兩份空成本陣列冒充合法空帳。舊成本鏈、參考標記、原來源字串及回執位元保持原樣；未知價格不被匯出／再匯入變成零。新版資料的舊寫入者保護持續存在；參考模式首次正式盤點也保留版本保護標記。

## P9 真實驗證與交付範圍

先凍結舊程式在「可用 7、未製作預留 2、製作中 1、架上實盤 9」的實際結果，再使用相同命令與來源驗證新盤點恰好維持可用 7。包含已收款未製作、先製作後收款、取消、配方原料、三位小數、零差異、盤盈未知成本、超過顯示上限、原單重送、狀態過期、錯店／世代、權限、偽造回覆、容量不足、晚期回滾與重啟；比較完整業務與成本前後像。實際原生／獨立瀏覽器／釘選 HTTPS／FileReader 或貼上／下載及四語兩風格手機尺寸引導須有證據。精確新安裝檔、真正舊版升級、實體設備、真人、規模及所有未完成 ERP 目標仍保持開放。
