# 原始財務表格搬家

M24 開發中。現有標準 JSON 搬家維持 M23 的行為；本規格的原始檔流程已接入同一搬家入口，尚未完成店家使用、發佈或完整 ERP 驗收。39 項業務義務與至少 45 項能力範圍維持。

## FF1 同一條工作流程

從「Agent 幫我搬家」交 CSV／TSV 或有界 XLSX，先整理原欄位，再看整批主檔、庫存、未收、未付及貸項。只詢問不知道或有歧義的事實；原系統與公司、來源編號、工作表、欄位與原文持續保留。店主核對後，沿用共同原單保存與收付款權限，不能新增一份平行的欠款清單。

## FF2 原檔、對照與補填

使用獨立版本 `pos-financial-file-migration/v1`，封存原始 UTF-8 文字或 XLSX 位元組、檔名、每張表的欄位用途、實際列號、隱藏資料、日期與金額格式及店主補填。既有 CSV／工作簿 v1 與標準 JSON 的歷史欄位意義不變。正式保存必須由同一解碼器從原始資料重算，不能信任 Agent 或畫面自稱正確的投影。

原始檔的所有有內容資料表都要核對。未知表格、歷史、未處理欄位或未完成幣別不能被略過，整批不顯示成功。原單需要穩定的來源編號；不能用第幾列、名稱或本地隨機編號替代。相同經濟單據不能換另一個批次編號重複增加餘額。

## FF3 金額與日期

保留原十進位文字並使用整數分。千位／小數符號和有歧義的日期順序由店主明確選擇，套用整欄後重算；不能四捨五入未知數字。已知的精度、幣別、日期或編號不能在補填格改成零或另一筆資料。公式與錯誤格的快取不是事實；須填入獨立核對的值。空白是未知，不能預填零、今天、到期日或匯率。

現階段款項帳使用 TWD。來源的其他幣別及 Excel 格式上的外幣標記仍須核對換算；選新台幣不會自動轉換原金額。庫存價值、未收請款、客戶貸項、未付請款與供應商貸項分開與原報表合計核對，不能用相抵後的淨額掩蓋錯誤。

## FF4 一次保存與可復原

新原始檔請求／回執使用明確的新版本，既有 JSON 格式14保持可讀。原始檔的新證據需要獨立版本保護，使用格式20；只在實際使用新原始檔流程時啟用。真正 M23 程式的暖開與冷開都必須拒絕不認識的新帳本，不能讓舊版保留不了原檔卻繼續修改資料。

店主的同一原操作原子保存主檔、庫存成本、原單、貸項、回執與保護索引。陳舊試算先重新核對；保存前拒絕不留下半批。回覆不明時保留完整原請求，重開只核對原編號。完整備份、跨儲存格式還原與日常收退款均須保留原始檔證據；已保存資料的受控更正與其他期初仍屬完整目標。

## FF5 驗收

實際桌面 SQLite、獨立瀏覽器及配對共用店面都需走選檔、缺少事實、試搬、確認、下載原紀錄、接續收付款及冷重開。包含四語、兩種風格、360px 畫面，錯誤角色、跨店、同編號不同內容、重複來源、差一分、公式快取、已知精度、隱藏資料、漏一表、存放額度、後段回滾、保存後回覆遺失、完整備份與真正前版控制。

解析器或自動測試通過不等於老人小孩已會使用、實體手機可用、所有廠牌可搬家或零 Bug。正式安全控制、完整對帳、其他期初與歷史、受控更正、公開營運及真人驗收保持開啟。
