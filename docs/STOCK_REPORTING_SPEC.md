# 實際成本報表與商品分析

此規格補充 I6／I11、C1–C5 與完整 ERP 原 31 項要求，不縮小完成門檻；成本帳仍須通過 I1–I12 才可公開啟用。本次前一輪為 progress：來源 `8957d38` 已接會計與三步售價試算，但營運首頁、銷售分析與商品排名仍重算參考成本。

## R1 一次讀取、同一份數字

啟用成本帳後，管理員的首頁、銷售分析、會計與匯出，使用同一 SQLite 快照中的帳務與業務來源。相同會計日期範圍的營收、銷貨成本與毛利須可逐分核對。商品參考成本改價不得重寫歷史。載入、過期回覆、錯誤與重新整理不能暫時拿參考成本冒充正式數字；未啟用時明示參考模式。

## R2 商品金額可加回總數

收入以原保存金額及明細分攤，保留商品原文；折扣、部分／完整退款、企業交付與退回、非回庫退貨及餐飲取消均依其原認列來源與日期。數量使用千分之一基本單位；金額與分攤用 BigInt 及明確區間取位，不把整筆混合成本硬除為兩位小數單價。商品成本加上明確列出的未分配調整，須等於總帳銷貨成本；其他帳上收入與商品收入的差額須可核對。

## R3 餐飲成本有原配方依據

新預訂由權威端保存當次菜品對原料的用量依據，後來改配方不能重寫。一次收款包含多種菜品時，每種原料的實際成本按當次原配方用量、固定品項順序及累計區間分攤；尾差守恆。只知道總原料用量、無原配方依據的舊多菜品訂單，保留未分配成本，不能猜比例。單一菜品可承接整筆成本。已付款取消的沖回、轉損耗與稍後補確認的成本沿用原依據。

## R4 未知與補確認

未知成本即使已售完仍不可當成零。依報表截止日決定是否已確認；補登在確認日期新增成本，不把後來知道的價格倒寫到過去期間。不可核對的舊帳、品項分攤及未知來源在商品排名、毛利及匯出中保持待確認，不把部分數值說成完整。非回庫退貨的損耗與銷貨成本沖回分開。

## R5 庫存金額與權限

管理員的商品積壓金額取目前實際可用庫存的成本區間，另保留預留量與已知／未知金額，不能用當前參考單價乘庫存充當資產。店員只讀既有權限內的收銀／餐飲銷售分析，不取得私人企業應收、供應商款項、完整總帳或全店實際資產估值；前後端均須驗真正帳號與範圍，偽造角色不得擴權。

## R6 簡短操作與驗證

保留既有報表、排名、篩選與匯出，不以隱藏原功能達標。主要畫面少字，大數字與待確認狀態優先；原因及調整明細再展開。明亮／海報、四語、360px、日期跨日、載入競爭及重新開啟皆有實際 renderer 驗證。原生帳務、兩個受驗證 HTTPS 身分、整數分守恆、退款與餐飲配方／成本確認必須有正負控制。真人與實體裝置驗收保持獨立，不以測試數或局部圖表證明整個 ERP 完成。
