# 越做越輕，功能照常

開發每一批功能時，同時檢查啟動、手機操作、前端資源、安裝依賴，以及常用資料讀取的成本。先記錄基準，再修改，再以同樣輸入重驗。檔案比較少不代表比較快。

這次把收銀、進貨、盤點、設定等功能頁改成需要時才載入；首頁保留直接載入。雲端設定讀取不載入 Supabase SDK，開啟雲端頁或主動同步時才載入。手動同步、離線快取及交易保存方式照常。移除已無法觸發的舊自動同步遮罩，合併重複的載入提示。

React、React DOM、Lucide、Supabase 瀏覽器 SDK、QRCode、JsBarcode 與相機掃碼套件，改列建置依賴。Vite 仍將實際需要的程式編入前端；桌面打包不必另外攜帶它們的 Node 套件副本。版本與鎖定來源不變，SQLite、伺服器及其他桌面執行依賴保留。打包結果仍須檢查檔案、實際載入及離線功能。

每次建置由 Vite 依實際編入的套件產生 `dist/THIRD_PARTY_LICENSES.txt`，保留完整授權文字，隨桌面程式及離線快取一起交付。原有 Node 套件聲明也保留；不能因精簡套件目錄而漏掉編譯產物需要的授權資料。

驗證分開記錄：

- 首次入口的完整靜態依賴，包括分出去的共用模組；另外記錄原始位元組與 gzip 體積。
- 完整前端、離線快取與實際安裝檔。延後載入仍需保留離線用的功能，入口變小不能當成安裝檔變小。
- 同一 Chromium、輸入與視窗下的啟動畫面及離線首頁；實體手機速度另外驗收。
- 延後載入的頁面逐一在線上與離線開啟，再重驗收款、庫存、原單號、草稿、共用店面及備份。
- 套件是否使用，要追查入口、動態載入與打包結果；搜尋沒命中只能列候選。清理產物前要核對來源、目前使用者與可回退版本。

後續持續處理翻譯資源、庫存與帳務大量資料的讀取、安裝依賴及手機文字密度。只對完成量測的部分報告改善，不以刪功能、語系、商店資料或復原保護換體積。

2026-10-18 的 Agent 搬家預檢使用按需載入。同一份候選原始碼實際各編譯一次，比較預檢面板立即載入與按需載入：完整首次入口為 480,475 → 470,019 gzip bytes，減少 10,456 bytes（2.18%）。相較前一包裝採購版本的 466,646 bytes，新增核對與翻譯後仍增加 0.72%；這不是實體手機速度或安裝檔體積的量測。

Agent 的首次任務索引由 11,223 → 1,308 UTF-8 bytes，原完整文件保留在獨立的舊協議指南。108 個實際 JS／CSS 資源、正式 Agent schemas 與任務指南保留離線快取。隱藏的 discovery 別名仍由公開伺服器提供，但不作為一般靜態主機安裝整套離線快取的必要條件，避免主機隱藏點開頭檔案時連帶失去離線收銀。
