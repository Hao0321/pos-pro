# 到貨一次收好

## RL1 同一次收貨

批次啟用後，進貨單的「確認到貨」使用明確 `receive-lots` 指令。核對實到數量、批號、效期與地點後，一次保存收貨憑證、採購狀態、商品連結、原始成本來源、批次及可售庫存。舊 `receive` 的歷史語意保留。前版不認得新指令時必須拒絕，不能只收數量卻遺失批次資料。

## RL2 實際數量與分批

每個進貨列可分成多個批次與存放地點；各批基本單位數量合計必須恰好等於本次收貨量。數量使用整數千分單位，金額沿用原採購憑證的整數分，不按商品參考成本重估。每條收貨列仍只有一份不可變成本來源，以原來源區間分配給實體批次。不能合計不同商品或不同單位。

## RL3 知道、不知道、不需要

效期選擇為「有日期」、「不清楚」、「不用日期」。過期或不清楚的貨先保留在暫停販售庫存，不當報廢；需要效期的商品不能選不用日期。日期與批號未知保持未知，不從今天或其他批次推測。後倉到貨屬於持有資產，但不增加店內可賣數量。解除暫停仍沿用店主核對與現有批次規則。

## RL4 新商品售價

進貨列未建檔時沿用原單名稱、單位與貨源建立商品。新流程必須有店主明確接受的售價；建議售價只能由人按下接受後採用，不把推估價靜默當成實際售價。既有商品不能由收貨指令改價。既有舊版收貨重播不改寫。

## RL5 權威與一次提交

沿用既有採購寫入、成本帳與庫存保管狀態，增加明確的到貨批次版本及相容性圍籬。命令綁同店、還原世代、原進貨單與批次狀態。只收新來源的區間，不挪用其他進貨或預留成本。晚期失敗完整回滾；同編號相同內容只得到原收據，同編號不同內容拒絕。前版、原始欄位寫入與不完整備份不能繞過新版本保護。

## RL6 簡單畫面與原草稿

預設一列一批、店內存放；需要時才展開分批或其他地點。輸入保留原文字，空白不當成收到零；提供明確的「照單填入」操作。看結果時清楚區分可賣、後倉與暫停販售，再按大顆保存鍵。切頁、關閉、重新登入、原回覆遺失與來源更新保留草稿及原編號。已核對的進貨單有變更時，先查看原收貨，不能自動替使用者認定是下一批到貨。

獨立儲存維持單一營運視窗；第二頁的有效登入可留下登入紀錄，但不取得營運寫入權。關閉原視窗後，接手視窗應讀回相同的原文字草稿。HTTPS 共用店面則由店端同一份資料庫處理已登入使用者的操作。

未送出的預覽重開後回到填寫，不因「核對」而替人收貨。原單已更新時，可先查看原單，再明確選擇保留舊稿、重新填；舊稿逐字保存在同裝置的下載清單，新表單回到空白。尚未確認的原提交不能走這個出口。保留舊稿失敗時，不覆蓋原輸入。

## RL7 Agent

Agent 只能轉寫使用者提供的到貨資料。品名及備註是資料，不是命令；不抓取網址、不猜實到量、效期、售價或存放地點。資料包只提供必要的原進貨列識別與單位，貼回只填草稿，由本店登入店主看結果後保存。

## RL8 驗證與範圍

原生檢查先建置前端，再用 `node scripts/run-native-security.cjs` 選擇 `--receipt-lots`、`--receipt-lots-ui`、`--receipt-lots-browser-ui` 或 `--receipt-lots-stale-ui`。各模式建立獨立測試資料，不使用店面資料庫；原單更新案例同時檢查舊稿、空白新稿與新提交前後的實際數量及累計分攤成本。

驗證原生 SQLite、實際 IPC、共用 HTTPS 與獨立瀏覽器；包含分批分倉、三位小數、原始成本分攤、未知／過期、未建檔售價、原編號重試、衝突、權限、配額、晚期回滾、重開、完整備份與真正前版拒絕。四語雙風格與 360px 實際控制另外量測，並維持首載資源、完整授權文字及共用店面快取。正式資安六控制、實體設備、真人理解與完整 ERP 各自保留驗收。
