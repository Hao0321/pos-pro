# 簡易工作台與完整 ERP 目標

## 先選工作區，資料共用

2.10.0 首頁提供兩個大入口，名稱先說使用者要做的事，再標 ERP／CRM：

- **顧客與點餐（CRM）——幫你照顧客人。** 會員、點數、儲值、點餐和預訂，讓接單與經營回頭客更方便。
- **營運管理（ERP）——幫你顧好貨和錢。** 商品、庫存、進貨、付款和帳務，知道還剩多少貨、今天賣了多少、有哪些款項要付。

兩個工作區沿用同一間店的資料與現有功能，切換不另建資料庫，也不用重新建商品、會員或單據。顧客點餐入口歸在 CRM；正式訂單的預留、出餐、收款與帳務仍沿用原本交易機制。現有會員 CRM 不代表企業聯絡人、商機、銷售應收等完整能力已完成。

2026-10-19 新增必要目標：訂位／候位、桌位容量及店家自訂會員福利，接續串接點餐、收銀和同一會員資料。範圍與 inline／Ocard 官方功能比較見 [訂位與會員福利規格](RESERVATIONS_LOYALTY_SPEC.md)；尚未完成的能力持續列入根目錄 `product-capabilities.json`，桌號點餐與基本集點不算已完成這些目標。

首頁保留「直接收銀」「快速建單」與六個常用捷徑；工作區內仍可搜尋全部工作。返回首頁會保留本次登入所選工作區，換帳號／角色或重新啟動則回到選擇入口。選工作區不會取得額外權限，也不會更動商品、訂單或庫存。

## 日常捷徑

2.9.0 起預設使用簡易首頁，將常用工作寫成使用者要做的事：賣東西、建單、預訂出餐、進貨退貨付款、開始營業收攤、商品庫存。白話搜尋可找手機、備份、退款等入口；「查看全部工作」及選單「全部功能」保留其他模組。簡易模式與大字模式是各裝置的畫面偏好，不改動店面交易或其他裝置的設定。

首頁的「接著處理」由實際購物車、開班狀態、採購應付及供應商待退餘額產生。點擊只帶往對應流程；金流、實際收貨、退貨、盤點與還原仍須看清楚內容後確認，不假設現金已收到或貨已到。

## 一次交給 Agent

1. 開啟「快速建單」，選賣東西、預訂餐點或叫貨進貨。
2. 按「複製建單資料給 Agent」，一次取得說明、當下店內品項、角色限制及範例。系統沒有連到外部 AI；資料要由使用者選擇交給自己的 Agent。資料依用途縮小：銷售／預訂不附成本與供應商，採購不附店內售價；不帶走內部配方及合作公司對照表。採購只有老闆帳號可用。
3. 把 Agent 完整回覆貼回來，直接核對；或匯入公司單據。可接受單一 JSON、UTF-8 BOM，或單一 JSON 程式碼區塊前後的一般說明；多份單據或額外結構資料會拒絕。說明文字不會當成指令執行。
4. 按「下一步」只補缺少的供應商或交付資料；看過單價、單位、數量、小計與合計後確認。單號、時間、店面、品項版本與角色驗證保持有效。

如果裝置不允許自動複製，會顯示可選取文字，並明示需要手動複製；不顯示未成功的複製訊息。這份資料包不是匿名寫入授權，協議也不會自行收款、收貨或轉帳。

2.10.0 起，這個裝置會接回同店面、同帳號與角色的未完成草稿；原 ID、時間與品項版本保持不變。保存失敗有提醒，待核對原單鎖定編輯；原編號結果確認後才清除。完整說明見 [Agent 建單協議](AGENT_DOCUMENT_PROTOCOL.md)。

## 目標仍保留完整範圍

`product-capabilities.json` 是完整目標的能力清單，含日常 UX、真人驗收、Agent 互通、POS、餐飲、銷售與應收、CRM、採購退貨與預付、庫存流水與成本、多倉批次、會計關帳與稅務、資產與對帳、製造、工時薪資、服務專案、多公司、外部整合、權限、備份、實機與安裝、可信更新及規模測量。

`implementation: available` 表示已有程式，不代表該能力在所有環境完成驗收。真人可用性與完整產品能力的狀態保持分開。`node scripts/check-capabilities.cjs` 驗證清單契約；加上 `--completion` 必須在任何能力未驗證時失敗。移除需求、重複 ID、舊版證據、缺少外部阻擋條件及私有證據路徑都不能通過。

本輪的程式和隔離測試不能替代真實長者、兒童、店員的無提示使用測試，也不能代替實際 iPhone、Android、印表機、店內 Wi-Fi 及長時間營業演練。完整 ERP 目標保持進行中。
