# 手機與電腦共用店面

更新：2026-10-16。以下以目前開發分支為準；新增的跨裝置完整備份與手機還原尚未重新打包進 2.16.0 安裝檔。全部店家、全部功能免費。

## 開啟方式

1. 在 Windows 桌面版登入老闆帳號，開啟「共用店面」。選擇電腦目前的私人網路位址，再啟動。
2. 電腦與手機連到同一個 Wi-Fi 或熱點，電腦保持開機與 POS 開啟。共用服務預設關閉，不會自行開放防火牆、建立公開隧道或設定背景自啟。
3. 第一次使用先下載電腦產生的店面憑證，比對畫面的 SHA-256 指紋後，在自己的手機建立信任。這是店面 HTTPS 憑證，與 Windows 安裝檔簽章是兩件事。
4. 產生一次性 QR 碼，手機掃描後登入同一間店的帳號。連結 5 分鐘內只能用一次，帳號角色由電腦驗證。
5. 在手機「營業前檢查」確認共同資料庫可讀、未確認交易紀錄可保存，再用測試資料驗一筆收款、退款與交班。

手機可從店面網址的 `/certificate.cer` 下載公用憑證；私鑰不提供給手機。只信任自己電腦產生、且已比對指紋的憑證。

iPhone／iPad 手動安裝憑證描述檔後，還需在設定中啟用 SSL/TLS 完整信任。[Apple 官方步驟](https://support.apple.com/en-us/102390)。Android 憑證管理位置依版本與廠商而異；Google 的文件說明安裝與移除入口，但不是本系統在所有 Android 瀏覽器上的驗收證明。[Google 憑證說明](https://support.google.com/pixelphone/answer/2844832?hl=en)。

網路位址或憑證更換時需重新核對配對。停止服務或重啟程式會撤銷現有裝置，須由電腦重新產生連結；可在電腦個別撤銷不用的裝置。此階段的登入期限為 8 小時、裝置配對期限為 24 小時。

## 共用資料與斷線

訂單、庫存、會員、掛單、儲值與交班由電腦 SQLite 保存。手機將交易送到相同服務，收到完整保存回覆後才顯示完成。電腦變更會推動手機重新讀取，手機變更也會通知桌面更新；畫面可能需要約兩秒反映其他裝置的操作，交易仍以資料庫當下的庫存核算。

店面外網中斷時，只要私人區網仍通暢就能繼續共用。手機與電腦的連線中斷時，手機停止保存，不會改用另一份本機庫存。已收到款項而未收到保存回覆時，先核對原單號；重新保存沿用原編號，不能再收一次款。待確認單號留在手機，請勿清除網站資料。

同一網址若換成另一間店的資料庫，原店面尚未確認的交易會被擋住；必須回到原店面核對。新 QR 連結開在既有手機分頁時也會重新初始化配對。

一般獨立 PWA 仍使用該裝置自己的資料，可在完成離線準備後單機使用；要共用店面，必須從桌面版產生的 `/shop/` 配對網址進入。手動雲端快照不提供多裝置交易衝突合併。

## 操作範圍與驗證

手機可收銀、查訂單／庫存／會員、進行授權的儲值、損耗、盤點與交班。店主也可在「設定 → 備份還原」下載完整備份、匯入電腦或瀏覽器的完整檔案，核對預覽後確認；目前帳號、憑證、原單與保護紀錄由電腦保留。未收到結果時沿用原編號查詢，手機不建立另一份營業資料庫。

較大的備份走店主專用上傳入口；接收檔案之前與之後都重新驗證配對、登入角色、憑證及 CSRF，一般交易傳輸上限不變。帳號過期、角色／密碼變更或裝置被撤銷時拒絕繼續。64 MiB 是檔案上限，不是已驗證的規模或效能承諾；現階段僅驗過隔離固定資料。

角色權限仍由電腦檢查，店員不能還原。硬體設定、印表機、帳號管理及雲端覆蓋請在店面電腦執行。促銷活動資料會保存，目前活動折扣仍須由老闆手動折讓套用。

15 項真實 HTTPS／SQLite 控制及 12 項實際 Electron／Chromium 畫面流程通過，涵蓋同時出售最後一份庫存、遺失回覆、手機斷線重開、桌面／手機雙向更新、角色偽造、CSRF／Origin／Host、撤銷與逾期、換店面資料庫、進貨保存等待、盤點衝突與設定／活動重開保存。測試使用獨立資料與精確信任的測試憑證；沒有全域關閉 TLS 驗證。

尚未驗收真實 iPhone／Android 的憑證安裝、休眠／背景恢復、使用者的 Wi-Fi／防火牆與實體印表機，不能宣稱所有設備無 Bug。正式預訂、原料預留與出餐見 [預訂出餐契約](RESTAURANT_WORKFLOW.md)；情境模板中的試賣演練仍保持獨立。
