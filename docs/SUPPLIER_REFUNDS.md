# 供應商退回款項與退款更正

已付款的貨退回後，「採購 → 原進貨單」會顯示供應商還待退回多少。實際收到錢，再按「記錄收到退款」。系統先帶入該張請款的待退金額，核對這次實收及銀行／本班現金後保存；分次退回時只改本次金額。備註可展開再填。

數字接受一般小數、全形與合法千分位，精確到分；科學記號、額外小數、負值或超過待退金額會拒絕。未完成的原始金額、方式、備註及更正原因依裝置、店面、還原版本及管理員分開保存，重開可接著填。草稿損壞或空間不足會保留並提示，不會先建立退款。

記錯時，在原退款按「更正這筆退款」。原金額及方式固定，可點常見原因或輸入自己的說明；原退款保留，另外記錄更正，再依實際情況重新登記正確款項。更正只處理原記錄，不會向銀行轉帳。

收到現金會增加明確核對班次的現金；更正現金退款會在核對的目前班次記錄相反支出。已關閉的舊班次不重寫。帳款或班次有改動時，要按「更新帳款與班次，保留輸入」重新核對；原欄位保留，不自行換班、改金額或改操作對象。

保存回覆不明時，先查原筆，沿用原編號。原完整請求、操作者、店面版本、實際退款／更正文件及現金流水都吻合後才確認；較晚已更正的退款會顯示其現況，不重新記回。查不到時只可重試這台裝置既有的完整待確認命令；命令或歷史不完整則保留草稿。其他待確認交易保留。此流程沿用既有採購、供應商核准、估價、現金與會計規則，沒有額外台帳或新的付款 API。

原始碼隔離驗證命令：

```sh
node scripts/run-native-security.cjs --supplier-refund
node scripts/run-native-security.cjs --supplier-refund-ui
node scripts/run-native-security.cjs --supplier-refund-browser-ui
```

UI 命令先使用當前 `npm run build` 輸出。自動化的原生／HTTPS／瀏覽器證據不等於真人長輩、兒童、實體手機或全部系統已完成驗收。
