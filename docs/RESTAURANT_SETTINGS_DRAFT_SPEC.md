# 產能與配方設定的未完成草稿

## S1 使用流程

老闆修改每日產能、時段產能、啟用接單、訂金模式或配方時，本機自動保留原輸入及所選商品／原料。空白與尚未填完的數字保持原文字，不能變成 0。離開頁面或重新啟動後接回原畫面；只有按「儲存預訂設定」才修改正式設定。

## S2 權限與並行

草稿依實際登入者、店面與還原世代分開，採用既有 Workspace Draft 的獨占 lease、CAS、配額警告及損壞原檔下載。店員不能接回老闆設定。不同視窗不能同時改同一份草稿；所有非同步回覆在套用前重新核對當前 lease、帳號及世代。

新設定指令沿用 configure、expectedConfig、正式 journal 與回執。草稿送出時使用伺服器確認的 storeId／epoch，寫入端在新寫入前核對店面、世代與真實 owner。既有已接受原編號先核對原簽章，再回原回執，不能重新套用設定。沒有新增交易或備份格式；舊執行程式能否讀寫仍須用真實舊版完整驗證，不能推論舊介面具有新保護。

舊流程同時帶入兩個 undefined 識別欄位時，沿用序列化後未提供識別的既有流程；只要任一識別實際有值，就必須完整且符合店面／世代。部分識別、空值、另一間店或過期世代不得降級為未帶識別。

## S3 設定有其他修改

恢復的草稿保留原 baseline。正式設定已變更時，不能直接保存。儲存前也會實際讀回最新設定；沒有收到更新通知時，仍會保留輸入並要求核對。按「保留輸入，重新核對」合併不同欄位；同一欄位衝突時顯示兩邊值，由使用者選「保留我填的」或「用店內最新」。選完再按儲存；核對本身不寫正式設定。隱藏的菜單、桌號與廚房列印設定從最新 baseline 保留，不能被草稿覆蓋。

## S4 未確認結果

正式指令的編號與原內容在異動前保存到既有 Pending Financial 與草稿原單證明。回覆中斷時保留原編號。重開畫面先查實際當前範圍的原回執與完整結果，必要時沿用原指令重試；確認前不顯示成功、不清草稿。全域復原完成也必須完成原設定畫面。保存後若另有更新，顯示原設定已保存，並載入店面最新設定。

未確認時的「核對上次設定」放在主畫面 inert 區域外的核對視窗，保留鍵盤焦點與手機可用高度。可直接沿用原編號核對，或回首頁／資料復原；不能放一個看得到卻無法點擊的重試按鈕。

## S5 驗證範圍

以隔離原生程式、實際 preload／IPC、憑證釘選 HTTPS 店面、真實兩視窗鎖、冷重載及完整資料備份檢查。覆蓋空白用量、離頁／重開、不同／相同欄位衝突、配額與損壞、帳號／世代切換、提交前拒絕及提交後回覆中斷。原生與瀏覽器成本模式、訂金開關、既有訂單／配方／帳務與舊版讀寫均保留回歸證據。

本規格不宣告完整 ERP、真人易用性、實體手機／印表機、外送平台、正式資安六控制或安裝／更新驗收完成。
