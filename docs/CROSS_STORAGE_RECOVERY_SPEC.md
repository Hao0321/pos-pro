# 桌面與瀏覽器完整搬家

狀態：開發分支已實作，進行完整回歸。延續完整備份 B1–B8、庫存 I1–I12 與原始 31 項 ERP，均不縮減。此階段只改來源與隔離測試，不操作真實店面、不公開啟用成本帳、不取代既有 2.16.0 安裝檔。

## X1 一份檔案，自動核對

沿用匯出、選檔、看重點、確認；系統辨識 SQLite／瀏覽器來源，自動核對對應格式。先驗原檔完整校驗及原保護圖，再轉換目前帳本，驗證轉換後完整資料與反向對應。來源未知、半份資料、診斷檔或不認識的欄位／版本保留原檔並拒絕，不猜成空資料。真正舊格式維持明確的保護紀錄缺口提示。

## X2 每份保護副本保留原格式

使用至少版本 3 的平面保護圖，書本節點標示自己的原始儲存格式；保留來源的原 JSON、內容校驗、來源編號、時間、原操作者、還原後邊界、全部索引及原復原回執。版本 1 的同格式與版本 2 的混合來源保持可讀；新的跨格式搬家至少使用版本 3，阻止尚不懂原始欄位保留的版本 2 寫入者覆蓋資料。使用新桌碼、加密顧客回執或原單備餐關聯時，使用版本 4，並阻止只懂版本 3 的寫入者。不同格式的來源合併後仍逐份用原格式驗證；不把原內容轉寫成新格式、不遞迴包入歷代完整備份。同編號不同內容拒絕。

## X3 設定值可逆，不猜型別

業務集合僅更換正式名稱；原單、金額、日期、成本事件和回執保持原樣。設定值另採明確編碼標記：原生文字對應瀏覽器的文字 JSON，瀏覽器的原 JSON 值對應帶旗標的原生儲存值。0、false、空字串、看起來像數字的文字及巢狀 JSON 均不得互相猜測或轉成缺值。原生普通文字往返後完全相同；瀏覽器原值往返也完全相同。原生 `_revision` 與還原執行期由新裝置重新產生，不冒充舊執行期。

目前帳號、密碼、連線與憑證仍由新裝置保留；舊角色不授權登入或升權。原始來源中的歷史帳號資料保持完整，僅供目前已驗證店主核對原紀錄。

店面編號及顧客追蹤密鑰是文字身份欄位；數字、布林、null 或物件不能當成其文字等價物。數字 0 的一般設定照常保留，文字「0」的店面編號也照常保留；不得因假值判斷而自動更換店面身份。

既有瀏覽器設定列若帶文字 `id`，也須完整往返；原生以可空的 `row_id` 保存，普通舊列不多輸出欄位。更新某一設定、建立報價及修改出餐設定不能重建或清除其他設定列的編碼與身份。報價資料需先解開儲存對應，再逐項驗證客戶價格、歷史版本及回執。

## X4 邊界與原編號保持有效

核對外來來源時，先把目前帳本可逆對應回該來源格式，再比較原有邊界。只有已證明等價的格式對應及原先允許的純相容性補齊可以接受；實際金額、數量、價格、設定、店面或原內容改變仍拒絕自動覆蓋。原單與成本來源不改編號、簽章內容或日期；找到舊結果先回原回執，再檢查新請求版本及時效。

## X5 原子保存與舊寫入者

預覽綁目前帳本、完整保護圖、整份輸入及轉換結果。確認在同一原子提交保留目前完整前像、合併所有格式的來源／索引／回執、替換資料、保存最終回執並旋轉執行期。晚期失敗、容量不足、衝突與來源錯誤全回滾；重送及重啟沿用原編號，不重做金流。

SQLite 新編碼值與混合來源須有持久版本柵欄；瀏覽器的新保護 metadata 版本也必須使不理解的新舊寫入者停止。先證明真正 2.16.0 對普通舊資料可寫，再證明使用新格式後拒絕寫入並保留資料，不能只用模擬舊程式。

配對手機提供店主備份入口及實際選檔預覽／確認。大檔案僅走固定的預覽路由，檔案接收前後均檢查當前裝置、登入、角色與 CSRF；一般 RPC 保持 1 MiB 上限。完整檔案以 UTF-8 位元組限制 64 MiB，專用請求僅另留少量封裝空間。已保護或跨格式資料不得走會丟失設定／索引的部分雲端同步。

## X6 實際驗證與簡短介面

凍結真正原生來源與固定雙向輸入，核對兩向來回、混合舊來源、超過 50 筆索引、已知／未知成本、原查詢與找回、去重及反覆匯出大小。使用實際原生 SQLite、獨立瀏覽器、完整回覆、FileReader、下載、認證 IPC／配對 HTTPS、兩種目前店主與舊操作者身份、偽造／店員、原子晚期失敗、資料更新、配額與回覆遺失重啟。

介面只說來源裝置、變動重點與保護紀錄數；詳細格式收起。保留四語、兩種風格、360px 和大按鈕。實體裝置、真人、正式六控制資安、規模及精確新安裝檔驗收分開，未完成時不宣稱完整 ERP、零 Bug 或正式交付。

## X7 獨立建立的原始欄位保持原樣

瀏覽器與 SQLite 各自實際建立商品、班別、原單、會員、供應商、促銷、掛單、分錄、損耗與儲值；不能只拿同一格式衍生的兩份測資證明互通。逐欄核對資料值、零值、型別與原本沒有的欄位。未知的商品建立／更新日期保持未知，不補成匯入當天。

SQLite 必要欄位與原始紀錄的差異，以同一還原交易內的校驗資料保存。未被後續業務改動的紀錄，在讀取、匯出及原編號回執保持來源原樣；真正的新交易照常反映現況，不掩蓋新變動。未知欄位在預覽拒絕，校驗資料損壞停止讀寫；晚期保存失敗須回滾帳本、原保護圖、執行期、柵欄及回執。會員儲值與小數損耗的原編號重送也必須回傳原欄位並保留目前餘額，不再扣庫或入款。
