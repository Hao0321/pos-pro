# 直接交表格搬家

## TM1 — 交檔案，不先寫 JSON

原有 Agent JSON 草稿繼續支援。增加 UTF-8 CSV、TSV 與分號分隔表格；先顯示檔名、資料類型、原系統及公司，辨識欄位後交給店主核對。無法唯一辨識的分隔符或欄位不猜。產品原編號、名稱、售價及基本單位缺少時只要求補上必要事實，不能用列號、名稱或零代替。

本階段不宣稱任意廠牌、原生 XLSX／XLS、期初或歷史帳搬家完成。店家可先從舊系統或 Excel 匯出 UTF-8 CSV。真人首次操作仍需另行驗收。

## TM2 — 原文、對照及修正一起保留

新增封閉的 `pos-tabular-migration/v1` 事實草稿：原系統、公司、檔名、完整原文字、分隔符、資料類型、原編號欄、逐欄用途、明確填入的共同基本單位及逐格修正。批次編號由完整內容決定。解析器在桌面、手機共用服務與瀏覽器使用同一實作，從原文和核對計畫重新推導資料；呼叫端不能傳入任意已投影結果。

不修剪來源值、不轉換數字、不吃掉前導零。雙引號、跳脫雙引號、儲存格內換行、空白及分解 Unicode 保留。格式錯誤、列寬不同、過量資料、重複用途及未選原編號阻止提交。原始標題可以相同，對照使用欄位置而非名稱。

原文永遠不因修正而改寫。修正必須顯示原值與新值，並一併進入原子回執及完整備份。下載搬入紀錄包含原文、對照、修正和永久來源編號對照。

## TM3 — 主檔入口不能藏掉帳款

共用欄位語彙辨識庫存、帳款、點數、儲值、累計消費與幣別。這些欄位不得改成未套用、改成其他用途或修成零；繼續交由既有主檔核對阻止非零或不明餘額。自訂欄位始終保留，不能據此宣稱所有財務欄位已辨識。公式、網址與文字只當資料，沒有執行或網路取用權。

欄位與儲存格調整只改草稿。最後沿用店主、店面、還原世代、當前資料及整批差異的核對與一次確認；所有三類主檔、原文、對照與回執仍在同一原子提交。

## TM4 — 保存、相容與驗收

未完成的欄位核對可在同帳號、同店面、同還原世代重開繼續。選檔完成順序不得覆蓋較新的輸入；原請求未先持久保存就不能提交。保留已提交原編號，遺失回覆後查回原結果。

前台只展開結構正確且用途在白名單內的表格草稿。損壞或未知欄位用途的 JSON 留在可下載的原文區，不把物件原型或其他非文字值送進欄位標籤，也不能因此讓整個畫面失效。

已使用表格來源的新資料庫增加 `agent-tabular-migration-v1` 的持久功能保護；瀏覽器及完整復原使用版本 11。真正前版必須拒絕不理解的新格式。沒有表格紀錄的舊資料不被無故升級成新格式。

驗收覆蓋 CSV／TSV 引號及換行、中文／前導零、同名標題、錯列寬、原編號缺少／重複、欄位對照、逐格修正、非零帳款不能隱藏、公式不執行、同來源重跑、冷重開、權限、保存失敗、完整備份及實際前版拒絕。操作驗證要走真正選檔、UI、資料庫／瀏覽器／配對 HTTPS，不以解析器測試取代。

CSV 的引號、雙引號跳脫及欄內換行依 [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180.html) 處理；TSV／分號使用相同文字保留規則。原生 XLSX 的 shared strings 與儲存格型別需要額外讀取，參考 [Microsoft Open XML 文件](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-the-shared-string-table)；目前不把 CSV 支援描述成原生 XLSX 支援。

欄位名稱的意思不能只靠字面猜測。例如 [Odoo 19 商品來源](https://raw.githubusercontent.com/odoo/odoo/19.0/addons/product/models/product_template.py) 的 `list_price` 是售價，`standard_price` 是成本；[ERPNext 商品文件](https://docs.frappe.io/erpnext/item) 另外描述標準售價。來源不明的「Standard Price」不自動當售價；只有店主明確指定用途後才進入核對。庫存量、應收應付、預收預付及會員儲值等常見欄名保留對帳。
