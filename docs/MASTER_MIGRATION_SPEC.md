# 商品、供應商與客戶搬入

## MM1 — 原始資料與身份

沿用 `pos-migration-draft/v1`。原系統、公司、類型與原編號組成永久來源鍵，保留原文字、前導零、原欄位及逐列位置。商品、供應商、客戶各有獨立身份；同名或電話相同只能提示，不能自行合併。既有來源對照優先；新對照遇到同名、條碼或電話候選，由店主選擇。重複來源編號、錯店、資料已變與未解決候選阻止整批提交。

## MM2 — 主檔與期初分開核對

本階段實作商品主檔（品名、條碼、基本單位、售價、參考成本、分類、供應商原編號）、供應商（名稱、聯絡人、電話、付款條件、備註）、客戶（姓名、電話、生日、備註）。商品的新庫存為零；來源主檔帶非零庫存、儲值、點數、累計消費或其他未支援的財務欄位時，不得靜默忽略，整批先停留於核對。期初、未結帳款及歷史參考仍依 AM3–AM4 實作與驗收，不把它們偽裝成一般交易。

空白不當零；商品缺售價或單位要補事實。生日僅接受可驗證的 ISO 日期或留空。供應商關聯用來源編號解析，找不到父列不能部分保存。未套用的來源欄位保留並列在核對結果。現有本店欄位不因來源缺欄而清空。

## MM3 — 核對與原子保存

前台先顯示選檔、貼上與「看核對結果」；技術原文與 Agent 指示只有展開才出現。結果顯示新增、更新、保留與待確認筆數及具體差異。本店欄位已有後續修改時，店主選擇保留本店或套用來源。相同原始內容重跑只取回原結果，不覆蓋本店後續編輯。

逐欄比較來源、本店與上次來源值。來源未改動的欄位保留本店後續修改；兩邊都改過的欄位直接顯示前後差異再選擇。來源這次省略的欄位仍保留舊來源基準；選「保留本店」時分別保存本店現值與最新來源值，下次來源更新仍能辨識衝突。

真正店主、店面、還原世代、來源原文、列選擇與當前資料摘要綁定同一次核對。提交前必須保存原請求；重開或回覆遺失時按原編號核對。商品、供應商、客戶、來源對照、原文與回執在同一 SQLite transaction 或單一 browser atomic record 保存。任一列失敗整批回滾。商品透過既有庫存成本權威建立，不繞過成本／批次帳。

## MM4 — 保護與驗收

保存歷史使用含摘要鏈的正式回執，不受一般活動記錄上限裁切；完整備份保留來源原文、對照與原編號保護。SQLite 功能 trigger 與瀏覽器復原版本 10 拒絕不了解搬家功能的舊版。還原前後須保留曾經使用的批次編號；移除原回執的舊備份不可讓同批次再寫一次。

直接表格來源另保留原文字、欄位用途及逐格修正，使用額外的 `agent-tabular-migration-v1` 功能保護與復原版本 11；只有已使用或需保留此保護的資料升級，既有 Agent JSON 資料維持其原版本。見 [表格搬家規格](TABULAR_MIGRATION_SPEC.md)。

驗收含新資料、更新、同名不同人、同條碼、跨公司同編號、前導零、缺父列、非零期初、原單重送及改內容、假店主／員工、過期核對、晚期 SQL／quota 失敗、回覆遺失、冷重開、完整備份與真實前版拒絕。以 native SQLite、瀏覽器及配對 HTTPS 的實際寫入驗證；真人首次操作、外部 Agent 與真實廠牌匯出另列未量測。
