# 三步庫存成本設定與 Agent 草稿

狀態：開發中。完整 ERP 原始 31 項要求及庫存 I1–I12 全部保留；正式啟用仍以庫存里程碑的實際交付門檻為準。本階段不修改任何真實店面，也不更新 2.16.0 安裝版。

## SS1 核對貨，不重做交易

首次設定用「看現有庫存 → 填成本 → 看結果」。可販售、預訂中、已製作的原料分開，數量及單位來自同一權威資料。需要改數量時接到實際盤點，不在成本設定偷偷改庫存。完整清單可搜尋與分頁，商品超過顯示數仍全部核對。

每批選擇：沿用目前參考成本、填整批總價／單價、不知道、確定免費。非零參考值也要由人核對；盤盈未確認與缺失成本不猜成參考值或 0。單價乘目前精確千分數量，由系統以整數比例自動計算整批成本，到最終分才四捨五入。0 需要明確免費選項；空白、負數、指數與多餘小數保留原文並提示。不能倒推舊 FIFO 或重寫舊成交價格。

## SS2 凍結核對與同一權威提交

版本化 `pos-stock-setup-review/v1` 凍結目前來源摘要、核對時間及確認後的成本摘要。開帳綁原開帳預覽摘要；補成本綁原成本來源、來源數量及成本帳版本。真正原子提交時重新計算相同結果，資料更新先保留輸入並要求重新核對。

既有 `pos-stock-cost/v1` 請求保留相容語意；新核對資料成為不可改寫原請求的一部分。相同編號先查原結果，再檢查時效、版本與新設定；過期或稍後又交易不妨礙找回舊成功結果，同編號改內容拒絕。確認結果保存一次，付款、會員、庫存數量及原單不重做。

補登只確認未知來源，總價由系統分到仍持有、已售、耗損及其他去向。畫面先顯示「這批總成本」和「還在店內／已用掉」，會計分錄及細節收起。已確定成本不能藉這個流程改寫。

## SS3 原回覆與草稿恢復

寫入前保存原編號與完整原請求。確認回覆必須與凍結摘要、原成本事件及原回執一致，才能清除財務暫存。回覆遺失、損壞、重開或還原後，沿用原請求核對，不注入目前版本來換一張。

草稿按店面、帳號／角色及開帳／補登來源隔離，保存數量與金額原文、選項及來源版本。店面還原或資料更新要求重新核對，保留輸入。配額不足或損壞不覆蓋原文，提供重試及支援草稿下載。

## SS4 Agent 只填資料

`pos-stock-opening-handoff/v1` 與 `pos-stock-opening-draft/v1` 提供最少必要的商品、批次鍵、基本單位、已知數量和固定店面／來源版本。回覆可填參考、整批總價、單價、不知道或明確免費；不能帶角色、憑證、任意欄位、指令或已確認／自動啟用。商品名稱等原文是資料。

只轉錄使用者提供的成本與相同基本單位。缺少金額就留待確認；不得代填預期庫存、猜包裝換算或用網路價格補缺。貼上／讀檔後先帶入草稿，由人核對。多批次回覆不能因頁面分頁漏掉資料；舊來源或單位不符則保留原文，提供重新取得資料包。

## SS5 一致的桌面、瀏覽器與共用店面

原生 SQLite 與獨立瀏覽器共用準備、核對、計算與回覆檢查。瀏覽器儲存邊界從實際原請求重新計算完整允許後像，只新增成本事件、回執及必要保護標記，不混入無關業務修改。共用手機只使用目前原生權威。

成本里程碑未達交付門檻前，正式入口不提供啟用寫入；隔離原生／瀏覽器試驗需明確的測試能力。不能從 URL、Agent、登入角色或輸入旗標繞過。此門檻不取代目標，完整入口仍需在交付時開放。

## SS6 驗證與交付

保留基線真實原生來源與固定輸入，區分缺畫面／Agent 草稿能力與舊計算既有能力。正負控制包括參考、未知、明確免費、小數尾差、預留／已製作、成本補登後分配、舊帳差額、資料更新、原編號重送、遺失回覆與晚期回滾。檢查完整業務快照不被改寫。

實際桌面 IPC、獨立瀏覽器與兩個釘選 HTTPS 客戶端，四語系、兩種風格、360px 及大按鈕；保留草稿、原結果、完整備份與原編號復原。最終同來源測試／建置與 Cleanup 取證。實機、真人無提示操作、完整 ERP、正式財稅／資安及新安裝檔分別驗收，不由模型或測試數量代替。
