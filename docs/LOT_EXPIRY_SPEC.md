# 批次、效期與先到期先出

完整 ERP 與 `WAREHOUSE_LOT_UNIT_SPEC.md` 的 W5 持續實作。所有功能免費；本階段不啟用公開成本設定、不更新安裝檔，不縮減 31 項公開義務。

## L1 原始資料

批號與效期綁定原成本來源的確切數量區間。可分批標註目前仍持有的數量，不能重疊或替已售出的歷史補造批次。沒填就顯示未知，不從品名或商品上的一般效期欄位猜測整批資料。每個商品是否必須填效期，由店主明確設定。

## L2 日期與順序

啟用時由店主核對店面時區；有效至某日表示該地當日結束前可用。系統按店面日期判斷，不跟隨手機時區。已觀察日期不倒退，調慢電腦時間不會使隔離品重新可售。

從可售庫存預留或出貨時，依有效期限排序；同效期沿用原入庫次序。必須管效期的商品，未知效期先暫停販售。非效期商品保留原流程，已明確到期的批次仍停止使用。已預留但過期的批次不得直接開始製作、收款或交付；更換或取消須保留原單與原料去向。

## L3 暫停販售與報廢分開

custody v2 新增 quarantined 狀態，保留實際存放地點及原來源。這些貨仍由店家持有，成本仍屬庫存，不能當成已報廢、遺失或供應商退貨。可售量移除和原流水同一筆保存。只有明確確認耗損後才認列損失。

日期更新由原生權威或獨立瀏覽器的單一原子寫入處理。店主設定或查詢可以引發到期核對；使用者付款等新操作須在其交易前取得新可售量。重試已保存的原單先查回執，不得重做原交易。未登入／偽造呼叫不能保存使用者提供的批次變更。

## L4 原單退回

退貨使用原單、原成本區間及目前批次資格。未過期且可售才回可售庫存；過期或必填但未知的部分回隔離，不能因退款就重新上架。不論回可售或隔離，成本沿原區間沖回；已耗損另留損失。前一版的返還、FIFO 次序與金額重播結果保持不變。

## L5 相容與驗證

新功能須有獨立必要 feature 與明確版本，不改寫 v1 custody 或既有歷史。預覽、成本補登、帳務與來源查詢須認得隔離量；完整備份保留每個批次、時區、所有狀態、原單與原來源。

必須驗證：兩倉兩批的 FEFO／轉倉／原退貨、未知資料、跨日與跨裝置時區、預留到期、價格補登及隔離持有成本、並行最後一批、回覆遺失、晚期回滾、完整備份、真正前一版正常讀寫及新格式拒絕。原生 SQLite、認證 IPC／HTTPS、獨立瀏覽器及四語簡單畫面分開留證。實體設備、真人理解、長時間營業、正式資安六控制及規模仍待獨立驗收。

## L6 耗損畫面與匯出

舊 `waste.cost` 保留原紀錄的參考單價，不改寫歷史。顯示和匯出的損失由同一成本讀取模型提供：正式來源區間優先，開帳前已凍結的分錄保留原金額，未確認成本顯示待確認。後續補登來源價格只改變衍生金額，不重做報廢。不得用今天的參考單價覆蓋原批次成本；模糊、缺失或重複歸屬不能當成零成本。員工畫面不顯示店主成本資料。
