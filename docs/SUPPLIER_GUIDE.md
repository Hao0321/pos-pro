# 供應商與預付款

2.16.0 提供此操作頁；2.15.1 不包含供應商帳本功能。本機安裝檔以成功的建置收據為準，見 [安裝與回退說明](INSTALLER_2_16_0.md)。所有店家、兩種模式及全部功能都免費。

## 最常用的三件事

1. 到「供應商與預付款」，選你的供應商。沒有名單時，按「新增或管理供應商」。同名供應商以代碼分開，不會把錢合在一起。
2. **實際付出訂金後**，按「已付訂金」，填金額與現金／銀行，核對後保存。這是在記錄已發生的付款，不會替你轉帳。
3. 貨到後，回進貨管理確認收貨、登錄供應商請款，再按「抵付請款」。系統可依到期日建議分配，仍由你核對。這一步用已付的錢抵帳，不會付第二次。

例如先付 NT$500，再收到兩張各 NT$200 的請款。抵付後兩張都付清，原預付款還有 NT$100 可用；現金或銀行只記錄原本的 NT$500 支出。進貨管理、應付餘額、帳務與收付報表都使用相同紀錄。

## 供應商退錢，或金額記錯了

- 尚未抵付的餘額實際退回時，按「收到退回款」，選原預付款、填收到的金額與原因。
- 已抵付的部分要退回，先在原紀錄按「解除這筆抵付」，再記錄實際收到退回款。解除只把金額還給原預付款餘額，不代表供應商已經退錢。
- 退款記錯，使用原紀錄的更正按鈕；整筆預付款記錯，先處理相關抵付、退款，再沖銷。原紀錄都會留下來。
- 原本直接付給單張請款的款項，回原採購處理。不能把其他預付款的餘額當作這張單的現金退款。

現金收付與更正需要目前開啟的班次；銀行方式記錄已核對的實際收付，不執行轉帳。報表顯示收付淨額，預付款抵帳不再算一次支出。

## 只有需要時才開啟另一帳號核准

預設一位管理員就能使用。在頁面下方展開「採購核對設定」，有兩個管理員帳號後，可啟用另一管理員帳號核准。

新採購先送審，另一帳號確認原品項、數量與金額後，才開放收貨、請款與付款。預付款分成「送審 → 另一帳號核准 → 實際付出後保存付款」；前兩步不動現金或存貨。自己的提案不能自己核准。已核准的付款提案只能用一次，即使之後沖銷也不能再用同一提案付款。

切回簡單流程只影響以後的新提案。原本待核准、已退回或已撤回的提案仍保留原要求。舊的正式採購可明確納入這次核准；系統不補造過去的核准人。

這是不同帳號之間的工作流程，不認證帳號背後是否為不同自然人，也不取代銀行的付款授權。

## 交給 Agent 幫忙填

展開「讓 Agent 幫我填付款草稿」，按「複製給 Agent 的說明」。把說明交給你的 Agent，讓它準備供應商、金額與方式，再把 JSON 貼回來，按「帶入並核對」。

簡單模式由你確認實際付款；核准模式會先送審。Agent 不能替你勾選已付款、指定核准人或提供登入資料。重複的草稿編號會開啟原紀錄供核對，即使內容被改過也不會再付款。協議欄位見 [Agent 建單協議](AGENT_DOCUMENT_PROTOCOL.md)。

## 手機、草稿與備份

電腦與配對手機共用同一間店的資料；各自可選繁中、English、日本語、简体中文，以及明亮或海報風格。切換外觀與語言保留已填的金額、備註與草稿原編號。頁面可查看較早的付款、抵付、退款與核准紀錄。

操作結果還在確認時，使用「確認原操作結果」，不要重建另一筆付款。畫面會保留原編號；關閉頁面後也能找回原草稿。若瀏覽器拒絕保存草稿，先保留畫面內容並核對，不要重複付款。

使用完整 JSON 備份。現有雲端快照無法保留全部新回執時，會拒絕覆蓋。使用新功能後，舊版程式不能繼續寫入這份帳本；即使還原舊備份，保護仍會保留。需要回到較早版本時，使用啟用前另存的資料副本。

目前自動驗收使用隔離店面、實際 Electron 與憑證固定的 HTTPS Chromium。實體手機信任設定、長者／兒童真人操作、母語校對、稅務及完整 ERP 能力仍須分別驗收。
