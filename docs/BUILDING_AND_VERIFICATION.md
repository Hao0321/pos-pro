# 一次完成建置與交付檢查

Windows x64、Node.js 24 以上，在專案目錄執行：

```powershell
npm install
npm run electron:build
```

預設輸出到 `release/<package.json 的版本>/`。該目錄必須是新目錄或空目錄；系統會拒絕覆寫既有版本。需要另外保存候選版時，可執行 `npm run electron:build -- --out release/<新的候選目錄>`。同一個工作區同時只允許一個正式安裝檔建置。

建置完成訊息 `POS_INSTALLER_BUILT` 只會在下列流程全部成功後出現：

1. 重建前端、準備 Electron 對應的原生套件、打包 NSIS 安裝檔。
2. 校準檢查器：實際測試越界路徑、重複檔名、遺漏或多出檔案、內容被改動、過期來源與產物、錯誤回執及版本等負控制。
3. 從剛產生的安裝檔安全解包，比對全部執行檔、ASAR、原生套件及每個延遲載入畫面。確認 SBOM、授權聲明與內嵌建置收據。
4. 在全新隔離資料夾啟動解包出的程式，透過實際登入、收銀、預訂、Agent 建單、報價、銷售、客戶預收與跨單抵付，以及供應商預付款、跨採購抵付、另一管理員核准及復原畫面核對保存結果，再重啟逐一核對所有營運集合。
5. 再次檢查來源及交付檔案雜湊，保存收據。任一步失敗，建置回傳非零，不會出現成功訊息。

工具會從 [7-Zip 官方 26.04 發布頁](https://github.com/ip7z/7zip/releases/tag/26.04)下載固定版本，先比對程式內鎖定的大小及 SHA-256，再解出並逐檔比對工具。檔案保存在 `.rd/build/tools-7zip-26.04/`，不執行安裝程序。第一次需要網路；有效快取可離線使用，快取不符時會拒絕執行。工具的授權文字一併保留，工具不隨 POS 安裝檔分發。

只想執行檢查器校準，可使用 `npm run test:delivery`；這不等於安裝檔已通過實際交付檢查。`npm run build` 只產生前端，也不等於正式安裝檔成功。

每次完整驗證的解包檔、交易測試資料、原始輸出、退出碼、校準與交付收據保存在 `.rd/build/delivery-*/`；成功收據另存 `.rd/build/installer-build-receipt.json`。失敗的建置留下自己的 `invocation-*/failure.json`。請以退出碼與對應收據確認結果，不能只看安裝檔是否存在或檔名是否正確。測試使用合成資料及獨立設定檔，不讀取實際店面資料；預設的自動流程驗證新裝與同版重啟。

安裝檔仍未簽章，維持人工更新；本流程不會發布 GitHub Release。NSIS 實際安裝移除、可信自動更新、完整舊版升級矩陣、實體手機及印表機、真人無提示操作、母語校對與完整 ERP 功能，需要各自的驗收證據。測試通過不代表零 Bug 或正式第三方資安認證。

有已核對的舊版隔離資料庫時，可加 `--upgrade-fixtures .rd/<清單.json>`，與新裝、重啟一起執行。清單是含 `version`、`source`、`sha256` 的陣列；來源只能在本專案 `.rd/` 下，必須是 WAL 已關閉的資料庫，雜湊必須符合。驗證器只複製到本次隔離資料夾，測試後再次核對來源雜湊。2.15.1 案例會核對舊客戶款項、收貨與退款，再從實際畫面記錄新預付款，並重送原本舊採購的正式請求確認沒有重複建單。
