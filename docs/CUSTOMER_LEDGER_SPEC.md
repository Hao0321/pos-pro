# 共用客戶、預收款與跨單抵付

2.15.0 功能規格。實際交付以對應建置及驗證收據為準；一般操作見 [客戶款項指南](CUSTOMER_GUIDE.md)。此流程不取代全 ERP 的 31 項原始範圍，所有店家與功能免費。

## C1 客戶身份與入口

客戶以店內固定代碼識別，名稱、聯絡方式與備註可修改；同名客戶不自動合併，既有銷售與報價保留當時名稱。新銷售單可沿用客戶名單，第一次接單時可在確認接單的流程中建立客戶。舊往來代碼可明確加入名單，不能靠名稱搬移款項。企業往來客戶與會員點數／儲值各保留來源，不假造會員交易。

## C2 一次收款、保留餘額

管理員選客戶，輸入實際收到的金額與現金／銀行，確認已收到才保存。建立一筆不可改寫的收款與原編號回執；現金在目前班次原子入帳。款項可先於交貨，未抵付部分保留為客戶預收餘額，不認列銷售收入。銀行僅記錄已核對的款項，沒有串接扣款。

帳務使用獨立的 2192「客戶預收款」；既有會員儲值沿用 2191。收到款項借記現金／銀行、貸記客戶預收；抵付時借記客戶預收、貸記應收。貨物交付的收入、成本及庫存仍沿用原銷售來源。設計參考 [IFRS 15 第 105–109 段](https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2024/issued/part-a/ifrs-15-revenue-from-contracts-with-customers.pdf?bypass=on)，不宣稱涵蓋所有合約、法域稅制或完成 IFRS 認證。

## C3 跨單抵付與更正

選一筆原收款，可以抵付同一客戶的多張交付請款。系統可按到期日建議分配，確認前列出每張單、金額與剩餘預收款；權威端重新核對客戶、單據版本、可抵付金額與原收款餘額。不能跨客戶、超額抵付、重複同一請款列或把同一收款複製成多筆現金收入。

抵付與解除抵付是獨立不可改寫的來源紀錄。解除可指定原抵付中的部分或全部，必須填理由，款項回到原收款餘額，不產生現金流水。原銷售逐張收款仍可使用，須扣除已有抵付；過期畫面的收款不能超收。每次銷售操作與客戶款項操作都核對客戶帳版本，保存後重讀、跨裝置刷新。

## C4 退回款項與交付退貨

退回未抵付餘額必須引用原收款，金額不能超過其可用餘額，沿用原付款方式。現金退款、更正與收款沖銷均須目前班次及實際核對確認；不可把解除抵付當成現金已退。更正退款保留原退款與原因，並回補原收款可用額。整筆收款沖銷前須解除所有有效抵付並先更正有效退款。

交付退貨／折讓仍引用原銷售來源。以預收抵付後產生的多收款，先明確解除對應抵付，再從原收款退回；原逐張收款的退款不能拿其他原收款的餘額重複退款。未做解除或退款前，畫面須分別呈現未收、交付多收、可用預收，不能把帳面可退金額顯示成現金已退。

## C5 原編號、歷史與復原

客戶帳異動與正式回執分別保存為 `customerEntries`、`customerOperations`，在同一 SQLite／瀏覽器原子提交內連同現金流水保存。帳版本嚴格遞增，從不可變事件重建客戶與款項餘額；回執與事件雙向一致。跨單抵付引用當次銷售版本，歷史核對同時檢查銷售操作所見的客戶帳版本，拒絕互相矛盾的先後關係。

發送前先保存原編號，再同步將草稿綁定相同編號及當時班次，最後才送至權威端。草稿保存失敗不得送出新操作；已送出的未知結果不得因草稿失敗而清除原編號。斷線或回覆不完整時保留及鎖住表單，沿用原內容核對，不能另建收款。核對在其他頁面完成時也清除相同原內容的草稿，不清除不同意圖。相同編號、不同內容拒絕。還原識別與原編號保護沿用現有復原協議；JSON 備份、SQLite 升級、受保護前像、瀏覽器原子紀錄及唯讀核對都必須含新集合。舊備份缺集合可讀作空，但覆蓋現有帳前仍須保護前像；不相容舊版須拒絕含新集合的完整備份。

原有銷售單不會因抵付被改寫，因此不能只靠新版銷售欄位阻止舊程式超收。首次保存客戶帳時，在同一 SQLite 交易內建立持久的功能寫入柵欄；只有目前相容連線註冊的功能支援函式可通過。舊程式或未註冊的寫入連線必須在修改前失敗，還原舊帳也不移除保護。回退程式須另有升級前資料副本；不能把升級後資料直接交給不支援的舊程式繼續收款。

## C6 操作與 Agent

入口以「客戶與款項」呈現：先選客戶，再顯示「收到款項」「抵付帳單」「退回餘額」及歷史。明亮／海報、四語系與 360px 畫面保持可用。金額、名稱、備註與單據代碼不因語言切換被改寫，未確認保存時不清空內容。

Agent 可提供版本化的客戶收款草稿，只填客戶、金額、方式與參考文字；系統核對本店身份與原草稿編號，先顯示核對畫面，必須由管理員明確確認已收到款項才保存。Agent 草稿不代表銀行已付款，也不能自動觸發扣款、跨客戶搬款或跳過核對。

## C7 驗收證據

必須實測：同名不同客戶、收款先於交貨、一筆收款抵付兩張單、剩餘餘額、分批解除與退款／更正、原逐單收款混用、退貨後的退款來源、現金交班、總帳借貸與營收不重複；另外測超額、不同客戶、資料改變、兩裝置競爭、同編號改內容、提交後斷線／重啟、晚期失敗回滾、保存空間不足、偽造／失效身份、完整備份及還原後原編號防重送。最後以交付安裝檔中的實際程式驗證主要畫面、交易與重啟。來源測試、實體設備、真人易用性與母語校對分開記錄。
