# 庫存去哪了：歷史與成本來源核對

狀態：開發中。完整 ERP 原始 31 項與庫存 I1–I12 保持不變；本功能不啟用新成本寫入，不取代正式交付、真人、實機或財稅驗收。

## SH1 先回答貨在哪裡

老闆從首頁或商品頁選「庫存去哪了」，搜尋商品，直接看到可賣、預留、已售／耗用、損耗及退供應商數量。金額、原單、成本來源與分錄按需展開。只有參考成本的舊店明確顯示尚未啟用成本帳，不補造歷史或把未知金額顯示為零。

## SH2 原操作及原成本區間

歷史來自完整驗證的不可改寫事件與實際業務資料，包含原操作、保存順序與時間、操作者、商品、單位、精確千分數量、原單、來源區間及當次全部新增分錄。依保存順序排列，回填日期不重排 FIFO。開帳、入庫、移動、退回、預留、耗用、損耗及成本確認分開；補成本不顯示為再次進貨。

選擇來源可查看原始數量、成本確認時間、目前各去向和引用這個來源的全部操作。原單包含多個來源時，來源篩選只計算該來源區間。當時未知與後來已確認的成本分開呈現；不重寫原交易、原分錄或原收款。供應商退貨差額依實際新增的分錄歸到該次操作，不以字串包含或同編號猜測歸屬。

## SH3 完整分頁與資料更新

商品及事件分頁均來自完整名單，超過 50 筆仍能找回第一筆。分頁綁店面、還原世代、成本帳及商品顯示版本；資料變更拒絕混用舊頁，保留選擇並提供重新核對。搜尋、來源與商品皆為資料，不執行任意程式、URL 或 Agent 指令。

## SH4 同一個唯讀權威

原生 SQLite、獨立瀏覽器與認證配對手機使用相同模型。原生及共享 IPC 驗證目前店主；獨立瀏覽器驗證實際帳號並在 Web Lock 中讀完整紀錄。事件鏈、原回執、成本持有量或對應業務有異常，停止呈現確定結果並保留資料，不自動修復、建立店面身份、改庫存、重送交易或另建離線帳。

## SH5 易讀與驗證

明亮／海報、繁中／英文／日文／簡中、360px、大字及觸控保持操作完整。四捨五入只發生於正式成本計算，顯示不反算成本。真人無提示操作仍需獨立驗收。

保留原生固定來源，正負控制包含超過 50 筆、同操作編號跨業務、補成本前後、混合來源、供應商暫記、原預留釋放與實際退回次序、損壞歷史、角色／來源變更、重新開啟與整份業務快照不變。回放觀察只傳遞純數值區間，不允許觀察者改變被驗證的事件或投影。效能以實際事件量量測，未量測規模不推論可用。
