# 自動廚房備餐單與紙張確認

狀態：開發中。延續原始31項完整ERP目標、I1–I12、B1–B8、X1–X7與K1–K8。所有店家、全部功能免費。本階段修改開發來源，不啟動實店印表機、公網服務、新安裝檔或Release。

## Q1 一次設定，新單自動排入

老闆先在硬體設定明確選好實際印表機，再啟用「接單後自動印備餐單」。不以範例IP、預設印表機名稱或僅隱藏按鈕代替確認。啟用只影響後續正式接單；既有預訂與顧客未接受請求不自動補印。原單接進正式出餐或店員新增正式預訂時，預留、正式回執與唯一備餐列印意圖在同一交易保存。

啟用或更換目的地時，由老闆確認測試紙張正確並保存目的地綁定。硬體設定後來變更而未重新核對時，暫停自動送印；不能把舊確認沿用到另一台印表機。

這份紙張確認綁定目前電腦的營運執行期，不放進可搬移帳本當作新電腦的確認。完整還原或換機後，需要重新核對該台電腦與印表機；既有紙張與嘗試紀錄保持原樣。

## Q2 印表機不是收款系統

備餐單優先顯示桌號、每日取餐號、餐點數量、備註、預訂日期時段與接單方式。品名、數量、原單與取餐號只取正式權威內容；前端不能送來任意收款、成本或印表機控制碼。備餐單標示「非收據」，金額如顯示則稱訂單金額，收款狀態以系統為準。長原始單號可保留於底部追溯。列印不能開錢箱、收款、改庫存、點數或成本。

## Q3 先保存嘗試，再送指令

列印工作及使用者操作回執獨立於財務帳本，使用唯一原編號與明確內容簽章。服務端原子領取工作，先保存嘗試編號、原工作、目的地與內容身分，再交外部傳輸。兩個工作器搶同一張單只允許一個領取成功。沒有明確設定時停止在可見的待處理狀態，不能偷偷送往範例位址。

## Q4 送出、紙張、未確認分開

TCP寫入完成或Windows列印佇列接收，只能顯示「已送印，請確認紙張」。使用者看到紙張並核對後，才可按「紙張正確」。中斷、逾時、程序退出或外部回覆遺失後，不猜是否印出、不自動重送正在嘗試的工作。保留目的地、嘗試與錯誤供核對。這個流程不宣稱物理世界的exactly-once列印。

## Q5 補印與取消可追溯

需補印時先讓使用者確認可能已印過；新副本使用新操作編號，印出明確「補印」及副本序號，仍指向同一正式原單。同操作重試不能多建立副本。尚未發送的備餐工作遇取消時不可繼續送印；已送出或結果不明者，取消通知與正式取消／退款同交易保存，避免廚房繼續製作。不同裝置的過時確認或補印不能覆蓋新的列印進度。

## Q6 重啟與完整備份不會亂印

完整備份包含列印工作與操作回執；不得刪掉舊工作、裁切索引或改寫原始保護副本。新資料格式具獨立版本柵欄，真正舊寫入者必須拒絕。恢復、跨格式搬移或整庫替換後，保留原狀態供查詢；來源執行期的待印工作不得在新執行期自動送出。需要印的由使用者核對後明確補印。原操作已在保護副本時，不可因目前查不到而重新建立。

## Q7 手機操作，同一台電腦送印

配對手機可看進度、確認紙張、要求補印，實際工作由店面電腦的單一權威送印，不在每台手機各印一次。權限沿用目前登入帳號；老闆才能改自動設定。拒絕匿名、偽造來源、失效／撤銷裝置與冒用角色。獨立瀏覽器保留、核對完整搬入資料；沒有店面原生傳輸時明確顯示無法自動送印。列印待核對不阻擋正常收銀。

## Q8 少字、四語、兩風格

主工作單只顯示列印狀態和下一個動作；列印目的地、嘗試、原始編號放在展開細節。支援繁中、英文、日文、簡中與明亮／海報風格、360px及大按鈕。動作要說明會送印、確認紙張或建立補印副本；不可把「系統收到」寫成「紙張成功」。

## Q9 實際驗證

先凍結d065469原生接單後沒有耐久廚房列印工作的基準，再驗同一份原單。使用實際SQLite、IPC、私人憑證釘選HTTPS、瀏覽器FileReader、完整備份、受控TCP接收器及Windows固定程式負控制。涵蓋接單晚期回滾、重複原單、兩個工作器、寫入前後中斷、外部回覆不明、重開、原編號重試、取消、補印競爭、權限撤銷、命令字元及新舊版本保護。模擬佇列、loopback或排入Windows佇列都不能當作實體紙張驗收。

## Q10 完整目標仍保留

原始31項義務不能因這個子流程通過而刪除、降級或標成全面完成。實體印表機字集／切紙／紙寬／缺紙、iPhone／Android、老人與兒童無提示操作、外送平台、長時間營業、正式六控制資安及精確新安裝檔仍各自驗收。本階段結果歸類PROGRESS，完整ERP目標持續進行。
