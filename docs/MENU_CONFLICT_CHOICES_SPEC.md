# 菜單兩個版本：選一下，再核對

M13g，開發來源驗證；不宣告完整 ERP、真人易用性或新安裝檔完成。

## C1 原輸入

菜單未完成的字串、數字尾點、留白、用量與單位繼續由既有私有草稿保存。原四欄草稿仍可讀；可選的單位基準與選擇紀錄只屬於畫面資料，不是業務授權、訂單或備份格式升級。無法保存時保留原快取與畫面，提供既有下載入口。

## C2 簡單選擇

同一欄有不同修改時，顯示餐點／份量／選項名稱與兩個可讀的值，按「保留我填的」或「用店內最新」。多項可先全選再個別調整。獨立欄位自動合併；刪除和另一方修改需要選擇。完整列的細節可展開，不顯示內部 JSON。

原料用量與單位是一個完整選擇，不能把另一方的克數接到自己的公斤。預設份量或預選項目若指向被移除的列，必須另選恢復該列或採用對方的選擇；不默默丟掉引用或獨立欄位。

## C3 新鮮來源與接回

每次核對／套用從原生或已配對店面重讀資料、商品及帳號店面範圍，不能只相信畫面收到的通知。選擇以本地原稿及對方菜單／商品單位摘要綁定；任何一邊改變，舊選擇失效。重新開啟可接回尚未套用的選擇，但仍需使用者按套用。晚到、換帳號、還原或已離開畫面的回覆不能覆寫新輸入。

## C4 保存邊界

套用只改草稿。仍須另外「下一步：核對菜單」取得目前原生價格／用量／成本預覽，再「保存並啟用菜單」。隱藏設定由現有預覽合併，原單保存與回覆中斷沿用原編號。核對與選擇不得收款、預留庫存、改配方或建立業務單。

## C5 驗證

先在實際原生畫面重現同欄售價只報錯沒有選擇的 RED，搭配獨立欄位合併正控制。候選涵蓋巢狀價格／名稱／組別／用量、刪除與引用、原始數字、選擇重開、漏通知、來源再次改變、店面／帳號變更與晚到結果；使用原生 SQLite 和憑證釘選 HTTPS，比較完整帳本。四語、兩風格與 360px 觸控幾何另外檢查；舊版、原單、顧客、Agent、款項及設定回歸保留。實體裝置、人類理解、正式六控制資安與所有原始 31 項公開能力另行驗收。
