# 語言與介面風格

2.15.0 的「客戶與款項」沿用兩種風格及四語系，包含預收、跨單抵付、退款、更正、Agent 草稿及原編號核對。切換時會保留原金額與備註；報表的動態分類說明也使用所選語言。較早的抵付與退款可按「顯示更早的紀錄」查看，完整歷史仍留在帳本。

2.11.0 新增「明亮簡約」，保留原本的海報風格。兩套都不限制功能，所有店家免費使用。

2.14.1 補上會員詳情的點數、訂單筆數、會員分群與四類促銷條件翻譯，同步時間也隨語言顯示。訂單、掛單、退貨、會員消費、庫存異動、損耗與稽核畫面使用所選語言的日期格式。手機會員詳情改用整個內容區，兩欄統計容納較長文字；關閉後返回原會員並還原鍵盤焦點。

登入前即可選語言，點一下風格預覽卡就能切換外觀。登入後可從側邊選單，或「設定 → 一般偏好」調整。手機頂端的語言圖示也可直接開啟選項，不必先找功能選單；按 Escape 或點畫面外側可收起。

第一次使用時，依裝置的語言優先順序選擇支援的語言。例如 English (US/UK) 使用英文、日本語使用日文、香港／繁體中文使用繁中、简体中文使用簡中；都不支援時預設繁中。一旦手動選過，就會優先沿用你的選擇。這份設定也供顧客點餐頁使用。

| 選項 | 提供內容 |
| --- | --- |
| 海報風格 | 鈷藍、黑、米白；保留淺色與深色模式 |
| 明亮簡約 | 白底、柔和藍色、清楚邊界、圓角與較輕的字體 |
| 語言 | 繁體中文、English、日本語、简体中文 |

偏好只保存在目前裝置。店面電腦可用中文，配對手機可用日文，仍共用同一間店的訂單與庫存。選擇不會重新載入 App，不會重建購物車或 Agent 草稿。瀏覽器拒絕保存偏好時仍可在本次使用中切換，畫面會說明下次需重新選擇。

## 翻譯範圍與資料

介面字典依功能拆分，包含導覽、工作區、收銀、會員、預訂出餐、採購、報價、銷售應收、庫存、帳務、設定、顧客點餐與丼飯演練。English 與日本語翻譯、简体中文轉換均隨程式提供，切換不呼叫外部翻譯服務。

商品、分類、客戶、供應商、地址、備註與示範菜名是資料，保留輸入的原文。語言不代表國家，也不變更 TWD／NT$、稅務規則、價格、單位、狀態代碼、單號或 Agent 協議。既有收據、匯出欄位與歷史紀錄不會因切換語言被重寫。

翻譯仍需要母語者校對；未建立字典的底層技術錯誤會保留原文供排查。本版不宣稱適用所有國家的稅制或已完成多幣別 ERP。

## 已實測

- 四語言在登入前、登入後、重新載入後可選用；儲存損壞、未知語言與保存拒絕有測試。
- 首次語言偵測、語言優先順序、中文 script／地區差異、手動選擇優先與保存失敗後的本次偏好有測試。
- 實際 Electron 畫面切換中保留購物車、售價、Agent 草稿原編號與未完成輸入，不會新增交易或扣庫存。
- 配對 HTTPS 手機選日文，電腦維持英文，共用同一店面資料。
- 360px 英文、日文與大字畫面，以及實際指標點選工作區、點餐送出。
- 明亮版標題、內文與主要按鈕實際對比至少 4.5:1。
- 顧客點餐與演練切換語言保留表單；演練資料仍與正式帳本分離。

這些是隔離資料與實際 Chromium 的測試，不代表實體手機、印表機或長者／兒童使用者已完成驗收。

## 維護翻譯

`public/i18n/catalogue/` 依功能拆分介面字典，鍵為繁體中文原文，每列依序是 English、日本語、简体中文，最後一個數字保留原始鍵順序。`messages.mjs` 組合字典，對外仍只提供三種翻譯。`core.mjs` 保留插值資料，只在明確的系統訊息使用訊息比對；`preferences.mjs` 的 `pos_display_preferences_v1` 不屬於店面交易、同步或備份集合。

修改後執行 `tests/i18n.test.js`、`tests/i18n-coverage.test.js` 與原生 `native-display-ui.cjs`。新增文字須維持 `{0}` 等參數一致。翻譯只改顯示端，避免以文字取代方式改寫商家資料或內部列舉值。
