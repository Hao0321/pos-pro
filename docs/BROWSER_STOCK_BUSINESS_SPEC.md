# 瀏覽器業務與成本一起保存

狀態：開發中；完整庫存成本 I1–I12 與原始 31 項 ERP 目標維持原範圍。所有功能免費，尚不公開開帳，不取代既有安裝版。

## B1 既有操作直接可用

獨立瀏覽器載入完整成本帳後，收銀、原單退貨、商品新增、損耗、採購收退貨、企業交付／退貨、餐飲預留／製作／收款／取消都沿用既有畫面。使用者不用另外記一筆成本。已接通的架上盤點保持原語意。

## B2 一次核對，一次保存

共用純業務規劃器從完整前像、原請求與實際帳號規劃允許的完整後像。儲存邊界重新規劃並比較整份後像，只有完全相符才能追加成本事件及原編號回執；不能用一般 allow/bypass 旗標帶過。未涉及成本的採購／銷售／餐飲設定也須符合精確正式計畫。無關帳本集合與舊成本前綴不變。

實際商品數量正規化為整數千分單位後再保存，成本使用既有 FIFO、整數分與固定來源規則。付款、點數、儲值、現金與應收應付不重做。商品售價或參考成本編輯不修改過去成本；有歷史的商品／單位不得刪改。庫存數量變更走盤點。

新成本保存另在同一筆完整帳本設定保存最後事件雜湊。載入／備份核對時，成本鏈必須與這個值相符，不能因為最後一次異動為零、已完整退貨或把兩個成本集合都清空而當成未開帳。既有不含此值的開發中帳本仍逐事件及凍結舊來源索引驗證；下一次新成本保存時補上。真正還原到開帳前的完整副本可回到參考模式，版本保護仍保留。

## B3 原單優先

原編號先核對請求、原業務來源、已保存成本回執及當前真實帳號，再檢查新操作時效；不得以目前資料重建舊回執。已開帳前的原單只走經凍結的舊來源，不能補造 FIFO。回覆遺失或重啟，沿用原請求核對，不換編號再次扣庫。

提交後回覆丟失可從同一份完整紀錄確認；提交前配額或驗證失敗保持原紀錄。無法確認原資料時維持不明狀態，不宣稱未提交；一般收銀及財務原單都必須驗完必要成本回執才清掉暫存。

## B4 相同權威與保護

瀏覽器的實際登入帳號／角色須匹配目前紀錄。退款、企業銷售與採購等老闆流程保持既有權限；同店配對手機仍由原生店面權威保存，斷線不建立付款／庫存副本。完整備份、保護還原、原編號索引與新裝置原單找回保持完整。

## B5 驗證與限制

先封存既有原生衍生成本帳與固定收銀請求，重現瀏覽器拒絕且整帳不變；候選使用相同來源／請求完成實際業務保存與精確成本回執。逐來源驗證量值守恆、兩種進價 FIFO、零／未知成本、小數尾差、原單部分到全部退回、預留製作與取消、採購差額、企業退回是否回庫、超過 50 筆歷史、晚期失敗與真正瀏覽器操作／重啟。

最終測試、建置、Cleanup、來源雜湊與 GitHub 開發版讀回綁定同一份來源。自動化通過不等於零 Bug、完整 ERP、真人易用、實體設備或精確新安裝檔交付；這些門檻保持開放。
