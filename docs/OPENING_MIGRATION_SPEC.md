# 原始資料開帳搬家

狀態：M17l 開發分支的庫存開帳流程；既有 2.16.0 安裝檔未更新。此規格是完整 ERP 搬家的一部分；尚未通過的步驟不能顯示「搬家完成」，應收、應付、預收預付、儲值、點數、歷史及受控撤回繼續依 AM4 完成。

## OM1 — 原始資料與用途

保留原始 `pos-migration-draft/v1`、CSV／TSV 或 XLSX 資料、來源系統與公司、欄位與逐格修正。主檔與期初共用來源身份，但分開辨認：商品、供應商與客戶不是新的交易；期初數量與價值也不是新的進貨或銷售。Agent 只準備事實，身份與核准由本店實際店主提供。

`opening-stock` 每列有原列編號、原商品編號、基本單位、確定的數量、庫存總價值及幣別。總價值直接來自已核對的原庫存報表；不得用售價代替成本。空白不是零，公式快取不是事實。Agent 明確提供的評價單價與總價值須相符；原報表已有總價值時，顯示用的四捨五入評價單價只保留為參考，不能蓋掉總值。只有缺少總值且有真正評價單價時，才用整數千分數量與最多十二位單價一次四捨五入到分。來源欄位缺少、同名異物、重複原編號、外幣與尚未支援的其他帳款不靜默略過。

CSV／TSV 保留引號、多行儲存格、空白列及實際列號；XLSX 保留原二進位、工作表與實際列號。已知數量或金額不能改寫成別的數字，只能補未知或需核對的原格；外幣不能靠勾選變成新台幣。沒有售價的庫存報表接已有來源商品對照，不能新建零元商品。新主檔入口也不能把庫存價值改成售價或忽略未知庫存價值；已保存的舊主檔來源解碼語意保留。

已知數字即使是負數、指數寫法、超過支援的小數位或範圍，也不能被歸成「未知」後改成零。這些資料先核對原帳或單位，畫面保留原值且不能任意替換。原日期格式不明時，可由店主用日期控制補已核對的日期；已知有效日期不能另改，原檔日期空白則保留空白，由店主確認的整批日期補足這個事實。

## OM2 — 一次核對

店主選取原資料與原報表日期作為切換日；只有來源唯一且明確的日期能預填，其他情況留空。系統接上已有永久對照，或依同一來源先準備主檔。顯示每列來源數量、原價值、本店現有數量與預計開帳後數量，依商品／單位分組及依幣別加總。缺少來源總額的檢查不能宣稱已和獨立原報表對平。前台使用「資料、看結果、確認」；技術原文預設收起，手機控制至少 48px，四語與兩種風格沿用既有流程。

試搬必須使用與正式寫入相同的主檔、庫存來源、數量及分毫計算權威。不能用一組簡單加總代替實際成本帳投影。公開的試搬結果要分清楚：已核對、待處理、已保存及仍未完成的整體切換。

換檔須先保留舊草稿並完整接入新原文，才開放欄位和確認；不能在重開、取得草稿鎖或切換檔案的短暫期間操作上一份資料。原待確認操作優先找回，不能被新檔覆蓋。

## OM3 — 原子開帳與原編號

`pos-opening-migration/v1` 請求綁原文、來源批次、切換日、實際店面／世代／店主、整份業務資料摘要與核對摘要。原編號在第一個寫入之前固定。主檔、來源對照、庫存、成本來源、開帳分錄、回執及版本保護在同一交易保存。不同內容不能重用原批次；已保存的來源期初列不能換檔名再加一次庫存。本店已有庫存或後續成本來源的衝突需明確核對，不能直接覆蓋。

期初存貨借記存貨，對應獨立開帳待對帳科目；不增加營收、採購、現金或一般盤盈。對應科目與差額持續顯示，整體搬家對帳完成前不藏進保留盈餘。已啟用成本帳沿用原來源；未啟用的帳本須先核對既有庫存及存貨帳，不能偷偷用未知成本開帳。真實前版 writer／reader 不能改寫新的開帳資料。

私有主檔子批次保留原始來源再推導，不把展開後的 Excel 再塞回 250 KB Agent JSON 限制；5,000 個原列的內部主檔與庫存角色不重複計算外部來源上限。子批次只在同一原子開帳交易保存，普通主檔 API 不接受；回執必須和原開帳批次完整綁定，獨立留下的子回執也視為不完整。新格式使用持久版本 13，保留既有較低層保護；後續一般主檔保存不能把版本降回 11／12。

## OM4 — 復原與驗收

必測原編號重跑與換檔重送、假店主／員工、切換日與精度、原來源及本店中途更新、成本來源與金額不符、晚期 SQL／quota 回滾、保存後回覆遺失、冷重開、完整備份及跨儲存還原。Native SQLite、獨立瀏覽器及實際配對 HTTPS 分別驗證，原文與新 ID 回執可下載。真人首次操作、真實廠牌檔案、實體裝置與大量資料長跑另列未驗收。

## 研究依據

- [ERPNext Stock Reconciliation](https://docs.frappe.io/erpnext/stock-reconciliation)：開帳用明確日期、商品、倉庫、數量、評價及獨立開帳對應科目，和一般庫存調整用途分開。
- [ERPNext Opening Balance in Accounts](https://docs.frappe.io/erpnext/opening-balance)：切換日承接原帳；未結單據與其他餘額分開帶入，避免控制科目重複認列，並核對開帳待對帳科目。

以上是本專案的工程設計依據；外部產品文件不證明本系統已完成切換或取得安全認證。
