# 整箱進貨、拆零使用的數量與原價

M17g 開發規格；整體 ERP、公開成本開帳、真人理解、實體設備及正式資安
驗收仍開放。所有店家、所有功能免費，保留 31 項原始義務及完整衍生範圍。

## PU1 — 輸入原本知道的事

使用者選供應商與商品，填「買幾箱／袋」「一箱有幾個基本單位」「每箱多少錢」。
系統同時顯示換算後的基本數量及整張原價，經店主核對再建單，不自動收貨。
沒有比例、原價、基本單位或無法精確換算時保留原文字，不猜商品名稱或網路價格。
庫存、分批收貨、請款和退貨數量一律以商品基本單位記錄；供應商包裝事實另保存。

新命令 `purchase-create-units` 建立 `procurement.version = 2` 的採購。
送出時另綁定店面供應商帳版本，並附本地店主核對的
`unitReview:{protocol:'pos-purchase-units-review/v1',confirmed:true,sourceSignature}`；
`sourceSignature` 綁定當時供應商及逐品項的商品單位、名稱、目錄單位與連結，
由實際保存邊界重新比對，Agent 草稿不得代填。
混合一般單位與包裝品項時，普通品項保留既有 `unitCost`；包裝品項使用
`costBasis: {protocol:'pos-purchase-units/v1', purchasedUnit,
purchasedQuantity, baseQuantityPerUnit, purchasedUnitPrice}`。四個輸入值除單位名稱
外均為原始十進位字串；包裝品項不得同時提供 `unitCost`。
`item.unit` 是基本單位，`item.qty` 必須精確等於原始包裝事實換算的基本數量。
相同進貨／基本單位的比例只能為一。綁定既有商品時必須與目前商品單位相同；
未建檔目錄商品的基本單位須由店主明確提供。
新建單介面以同一個新版命令處理；基本單位輸入使用「進貨單位＝基本單位、
比例＝1」的明確原價事實。舊 API／原 Agent 的 v1 採購及混合品項仍保留原語意。

`purchase-create` 仍僅建立原格式，不得悄悄忽略 `costBasis`。原報價／舊 Agent
協議保持原語意；不將不相容的報價或私有快建認領包裝版。

## PU2 — 同一份整數數量與分毫

沿用同一個十進位文字解析器。數量／比例最多三位小數，金額最多兩位小數；
不接受科學記號、負值、空白當零、超大值或換算後不足最小基本量的結果。
保留原始前導零和小數文字，計算時使用整數最小量與 BigInt，不先算浮點單位價。

原價 = 包裝數量 × 每包裝價格，按既有半入規則一次換成整數分。
基本數量 = 包裝數量 × 每包裝基本數量，必須能精確表示為基本毫單位。
原單為 1 箱、每箱 3 瓶、100.00 元時，總額永遠是 10,000 分；
不能改成 33.33 × 3 = 99.99 元。

`purchaseLineCents(item, quantity)` 是採購品項的唯一金額權威：舊品項逐字沿用
舊單價計算；新包裝品項按原價／原基本量計算累計整數分。
分次收貨取累計差額，最後一批帶走剩餘分；請款和退貨沿用現有原文件餘額配置，
保留選定的請款單、原成本及差額處理，不新增另一套可修改的成本或庫存帳。
原單、核准材料、收貨／請款／退貨、庫存來源及完整備份都保留 `costBasis`。

每基本單位的約略參考成本只供顯示／商品參考，不得回乘成供應商原價或實際成本。
既有商品售價及參考成本不因收貨被改寫。未建檔商品須明確確認售價，包裝流程
不能沿用舊式自動加成價格。未啟用成本帳的既有利潤仍屬參考，不能宣稱精確 FIFO。
成本帳啟用後的收貨來源直接使用原單配置的分毫，不使用四捨五入的參考單價。

## PU3 — 原單、原編號與版本保護

店主身分在原生／共用連線的實際權限邊界驗證。新建單核對目前商品基本單位、
供應商與輸入包裝事實；送出前保存原編號、原文字及完整指令。
同編號改內容、錯店、舊 epoch、失效供應商帳版本及變更來源拒絕。
回覆遺失、重開或全域原單核對必須找到同一份完整採購；只清除完全相同的原稿。
晚期 SQL／瀏覽器配額失敗回滾所有紀錄；寫入後失聯不得誤報未保存再建另一筆。

使用 `procurement-unit-pricing-v1` 功能標記、
`procurementUnitPricingVersionFence` 與持久 SQL 保護，完整備份列出功能。
真正前一版原始碼必須拒絕讀寫不支援的採購／備份；移除標記並重算封包 hash
也不能略過版本與原價核對。一般 v1 採購及歷史重播仍完全不變。
相容性必須涵蓋尚未啟用成本帳與已啟用成本／批次的兩種店面。

## PU4 — 簡單表單與 Agent

一般採購仍可直接填基本數量與基本單價；「用箱／袋進貨」才展開包裝事實。
常用流程保持「選商品 → 填原單 → 看結果 → 確認」。手機採卡片排版，
主要動作至少 56px；明亮／海報、繁中／英／日／簡中均需實際操作。
共用草稿保存、互斥、保留原稿與下載機制，保留未完成及不確定原單。
歷史資料只能作已標示的參考，不用約略單位成本替代包裝原價。

Agent 僅轉錄指定店面、店主、供應商與基本單位下的已知事實。
新增獨立 `pos-purchase-units-draft/v1` 草稿格式，保留原始文字及可編輯品項；
不得自行猜比例／價格、讀取 URL、代替店主核對或自行建單。貼入後仍經相同
計算及原生驗證。使用者已選定的範圍、日期及其他未授權給 Agent 的欄位保留。

## PU5 — 驗證與精簡

以現有計算器重現 100 元分為 3 瓶後少 1 分的表示能力缺口；
以相同輸入證明新原價精確保留，並保留可整除的普通採購作有效對照。
涵蓋多箱／半箱／公斤、三次收貨、跨請款單部分退貨、最後餘數、零元明確事實、
混合品項、未建檔／既有商品、來源變更、偽造身分、晚期失敗、回覆遺失重開、
備份／跨儲存還原、真正前一版讀寫者、兩位店主競爭與舊採購回歸。

核對完整 UI → adapter → 原子保存 → 回覆 → 畫面 → 重開資料鏈。
一次讀取的商品、供應商、原單、來源與評量器版本均須有實際執行證據。
測量相同採購頁／建立頁的編譯依賴、首次入口及離線完整性，並精簡重複表單與
金額邏輯；不以刪功能、語系、復原或授權換體積，不推論安裝檔或實機速度。
