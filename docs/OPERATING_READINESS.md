## 共用店面與正式出餐

手機從桌面版「共用店面」產生的私人區網 HTTPS 配對網址登入，使用同一個電腦 SQLite 資料庫。操作、庫存與班別以電腦為權威，手機斷線停止保存並保留原操作編號；返回頁面後會恢復同步。電腦須保持開機，手機與電腦須保持區網連通。外網可中斷。配對與憑證說明見 [共用店面](SHARED_STORE.md)。

「預訂出餐」支援預訂、現場與外送登記，按成品或原料／包材預留庫存，限制每日／每 15 分鐘產能，分配不重用的每日取餐號。付款、備餐與交付分開；尚未製作取消可釋放，已製作取消保留耗用、產能及損耗費用。正式流程、完整備份與限制見 [預訂出餐契約](RESTAURANT_WORKFLOW.md)。情境模板中的試賣演練保持獨立。

## 已修正的營業問題

- 收銀、退款、儲值、現金流水、進貨、盤點與預訂的保存回覆須含原操作身份及完整紀錄；回覆中斷保留同一編號，重試不重複扣庫或收款。
- 進貨的庫存、採購進度、供應商目錄及回執一起提交；盤點與目錄拒絕覆蓋其他裝置的新資料。
- 儲值實收現金計入原班別，贈額不計現金；累計部分退款與跨班退款按實際流水核對。
- 混合付款的現金、非現金分別入帳；已製作取消的損耗按凍結單位成本計算，銷售退款後仍保留實際費用。已扣庫、入帳損耗不可直接刪除。
- 備份保留所有資料集合、營業設定、明確零值、原時間、預訂與操作回執。相同時間的紀錄排序不再讓內容版本誤判改變；異常還原全數回滾。
- 硬體偏好整批原子保存，失敗保留輸入並恢復按鈕；下載或列印指令送出要求實際確認，不顯示未取得的完成證明。
- 損耗支援最多三位小數的原料數量，拒絕零值、負值及超過庫存；重複點擊只送一筆。保存失敗保留輸入，原編號重試確認後關閉原表單，避免再次扣庫。
- 損耗月份、帳務起迄、費用及進貨日期按本地日曆一致處理；促銷日期輸入保留本地時間，保存成明確時間點，拒絕倒置期間，兼容舊本地時間紀錄。
- 共用頁面返回與重新可見後恢復同步；電腦網路位址變更時更正選擇或要求重新啟動配對。營業前檢查按原料判斷可接量。
- 出餐工作單優先顯示，接單表單按需展開；手機輸入、收款及取消面板跟隨可見視窗。

## 使用限制與試賣前實機驗收

- **真實手機與設備尚未驗收。** iPhone／Android 的憑證信任、休眠、相機、店面 Wi-Fi／防火牆及實體印表機，須用自己實際使用的設備完成接單、收款、交付、取消退款、斷線恢復、交班與備份還原。
- **獨立瀏覽器資料仍各自保存。** 獨立 PWA 可單機離線；要手機／電腦共用，須使用共用店面的配對入口，不會自動合併不同瀏覽器的 localStorage。
- **正式預訂採全額收款與全單取消。** 部分預付、部分取消、加料組合、LINE 自動接單與外送平台串接仍未實作。促銷頁目前保存活動資料，結帳折扣由老闆手動套用。
- **預訂使用完整 JSON 備份。** 既有雲端快照尚未涵蓋全部預訂與回執，啟用正式預訂後會拒絕不完整同步；部署中的 Supabase／LINE 等服務未驗收。共用店面不依賴雲端服務。
- **安裝包未簽章、採人工更新。** 本機檔案與 GitHub Release 需分開核對，見 [2.9.0 安裝說明](INSTALLER_2_9_0.md)。原店面資料未被測試修改；未替使用者啟動防火牆、公網隧道、自動啟動或安裝憑證。

開發者使用 Node 24，可執行 `npm test`、`npm run test:native`、`npm run test:desktop`、`npm run test:offline`、`npm run test:mobile`、`npm run test:shifts`、`npm run test:scenarios`、`npm run test:scenario-ui`、`npm run test:business`、`npm run test:shared`、`npm run test:shared-ui`、`npm run test:restaurant`、`npm run test:restaurant-ui`、`npm run test:operations-ui`、`npm run test:procurement`、`npm run test:procurement-returns`、`npm run test:procurement-ui`、`npm run test:agent-ui`。原生 runner 要求真實 child exit 與成功 marker。
