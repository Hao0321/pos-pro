# 一般供應商退貨

採購 → 選進貨單 → 辦理退貨。填實際退回的數量，選常用原因或直接寫原因，確認「貨已退回，記好退貨」。退貨金額依原採購單的累計分攤自動計算，庫存與帳款一起更新；收到退款時，再用既有的退款功能記錄款項。

輸入會依店面、帳號與帳本世代保存。關掉視窗、切頁或重開後可接續；已輸入的文字不會隨語言切換而改寫。數量接受一般小數、全形數字與最多三位小數，拒絕指數、十六進位及超精度輸入。包裝採購依原單基礎單位退貨，不重新捏造四捨五入後單價。同商品多列合計不能超過現有庫存。

保存前會核對原採購、供應商、該採購商品的名稱／單位／庫存、成本與批次模式；無關商品異動不會使草稿失效。資料變更時可「更新採購與庫存，保留輸入」。更換退貨來源也保留數量與原因，仍須核對新來源可退量。店面啟用批次後必須使用原有批次退貨流程，這裡不自動啟用成本、倉庫或批次。

若保存回覆中斷，先查原退貨。草稿只保存原編號、時間與摘要；完整命令仍由既有待確認紀錄保管。核對使用實際退貨、庫存回執與已啟用的成本帳，不重送假成功、不以舊庫存覆蓋後續異動、不清除別筆待確認操作。查不到完整原紀錄時保留輸入，不能另建一筆假裝完成。

## 讓 Agent 幫忙

表單內「讓 Agent 幫我填」→ 複製說明 → 把原始退貨資料交給自己的 Agent → 貼回 → 帶入後核對。`pos-ordinary-supplier-return-draft/v1` 只轉錄單一採購與已選來源，綁定店面、帳本世代、原採購與相關庫存摘要。Agent 不猜數量、原因、價格、稅額或退款；不取網址、執行資料內指令或索取帳密。來源合計若有提供，必須等於原採購分攤結果；後續修改數量也保留該合計核對，只有明確改用手動核對才解除。

這是本專案的代填格式，沒有自動退貨、付款或供應商認可權限。它不同於已存在的批次退貨 `pos-supplier-return-draft/v1`；不能互換。公開 schema 和本機模擬 Agent 測試不代表外部 Agent 服務已驗收或採用。

本次交付限原始碼。真人、實體手機、跨服務 Agent 及完整產品驗收仍待完成，安裝檔不會因此自動更新。
