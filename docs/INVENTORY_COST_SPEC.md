## I1 可用、預留與耗用分開

每筆入庫、出售、交付、預留、釋放、耗用、退回與盤點差異，都保留原操作、單據、帳號、商品、單位、數量與成本來源。`products.stock` 是可用數量，不能當成包含所有預訂與製作中材料的實體總量。未收款預訂保留的原料／製作中成本仍屬持有成本；收款認列或確定耗損時，才依現有業務來源轉出，不能在預留與付款時扣兩次。

## I2 核對期初，不猜舊歷史

已有店面先預覽目前現貨、未收款預訂／製作中、舊成本資料與總帳差異，管理員明確確認後啟用。零成本與不知道成本分開。可沿用經核對的參考值、輸入確認值或保留待確認；不能把缺值當零、倒推未知批次或改寫過去成交資料。來源摘要版本固定，盤點或交易期間資料變動需重新核對，輸入與原編號保留。

開帳以當時已保存的來源及舊單缺失成本估值為固定前像，不再隨日後商品參考成本變動。開帳分錄只補足成本帳與既有存貨總帳的差額，避免再認列一次舊進貨。大型名單可分頁核對；確認請求使用權威端摘要與少量覆寫，不能受頁面筆數限制而漏商品。未啟用前明確呈現參考成本模式，不冒充已完成正式估值。

## I3 先進先出、整數數量與金額

預設成本政策固定為先進先出（FIFO），以實際保存的入庫次序取成本，不用回填日期重排。內部數量為千分之一基本單位，金額為整數分；乘除用精確整數比例與明確四捨五入，不能以浮點相乘推算尾差。來源成本區間保存偏移與數量；完整取用或退回後，分配金額必須恰好等於來源總成本。真實批次、效期、FEFO、單位換算與多倉仍是原始目標，成本層不冒稱實體批次。

成本公式與費用認列設計參考 [IAS 2 官方摘要](https://www.ifrs.org/issued-standards/list-of-standards/ias-2-inventories/)；此里程碑不是完整 IFRS、可變現淨值、稅務或會計師認證。

## I4 接通全部業務來源

| 來源 | 必須證明的行為 |
| --- | --- |
| 商品新增、匯入與編輯 | 正數期初有來源；編輯價格不回寫已變動庫存；數量改用可追溯調整；有歷史商品不能直接刪掉 |
| POS 結帳與部分／完整退款 | 成交保存實際成本分配；原單退回沿用原成本；現金、點數與儲值規則不重做 |
| 採購收貨與退貨 | 每次收貨取原保存的行成本及尾差；退貨核對來源與實際轉出成本；不重複現金或庫存 |
| 企業銷售交付與退貨 | 交付才轉出；退貨是否回庫沿用原實際選擇及成本分配 |
| 預訂、製作、收款與取消 | 預留使可用減少但保留持有成本；未開始取消釋放原層與原次序；已製作取消保留耗損；支付不再扣數量 |
| 損耗與盤點 | 損耗轉出一次；盤盈、盤虧、待確認成本及權限均有原操作與理由 |

預訂可以先製作後收款，不能假設只在付款後才耗料。已付款且已製作的取消，要能從銷貨成本轉為耗損，不能退回不存在的原料或再扣一次。

## I5 退回、重用與成本差額

部分退回引用原轉出區間，累計不得超額；重送不重複恢復。實際售後退回以新入庫次序重新可用，同一次退回依原轉出區間次序排列，仍保留原成本來源；尚未耗用的預留釋放恢復原次序。供應商同品項退貨不能假定現在剩下的都是原進貨成本；原請款折抵與實際轉出成本不同時，保留明確成本差額，應付與存貨都可核對。

## I6 不確定成本保持不確定

待確認的成本層可追蹤數量，不把未知價格變成零。操作及報表顯示「成本待確認」，總帳與匯出標明估值尚未完整，不能呈現虛假的完整毛利或資產。補確認原來源成本，須以新操作分配到仍持有、已售、已耗損及其他已轉出區間，保留原未知紀錄與本次確認時間；不改原收款或重送原交易。未核對成本的折抵用明確暫記及待處理狀態，不能冒充已確定收益。

## I7 原子提交與完整回執

成本事件、原業務文件、可用庫存、金流、角色與正式回執在同一交易提交。原編號先查原結果，再檢查新操作時效與版本；沿用完整原請求，不注入目前成本帳版本。變更原業務內容仍拒絕。提交後遺失回覆、重新開啟及重試，只保存一次；晚期 SQL 失敗完整回滾。驗證實際前像、來源與累計成本，而非只對現在總數。

## I8 相容性、備份與一間店的權威

新不可改寫事件及回執包含於 SQLite、瀏覽器完整集合、備份、保護還原、原編號索引與復原引導。新功能寫入柵欄阻擋不認識成本帳的舊寫入者；舊單不補造過去的 FIFO 歷史。還原舊備份後仍保留相容性保護與不明原交易恢復能力。雲端拒絕部分覆蓋。配對手機使用同一個權威端，斷線不建立離線庫存／付款副本。

## I9 白話操作與盤點

庫存畫面直接回答「進了多少、用在哪裡、還剩多少」，需要時再展開成本與來源。盤點清楚區分貨架實數、已預留未製作與製作中；由系統帶出已知預留，不能讓使用者不知情重複扣除或把缺料變成負庫存。未保存表單、同一份草稿與原編號可恢復。明亮／海報、繁中／英文／日文／簡中、360px 與大字模式都保持操作完整；真人驗收另列。

## I10 Agent 只準備草稿

提供版本化的盤點／期初資料草稿與最小必要資料包：固定店面與原編號、商品、明確數量意義及待核對值。來源是資料，未知欄位、登入憑證、角色、已盤點確認、任意指令與自動過帳均拒絕。使用者貼上即可核對；不需理解協議欄位。原編號復原、資料更新與成本未知有清楚下一步，不以換編號消除不明結果。

## I11 帳務不重複、成本可追溯

成本來源接入銷貨成本、耗損、存貨、期初差額及供應商退貨成本差額；沿用原採購應付、營收與現金來源。原預收、預付及抵付不因新成本帳再次產生現金。僅在可用與預留間移動時不產生成本費用。舊單缺失成本估值明確凍結，不讓商品價格更新重寫歷史報表；新成交保存整筆精確成本，不要求混合成本硬除成兩位小數單價。

新成本分錄明確標示 `amountUnit: cents`，借貸金額使用整數 `debitCents`／`creditCents`，不先除以 100 再轉回分。報表整合須同時辨識舊小數金額與此單位，不能把分當成元。開發分支已接會計畫面與成本售價試算；首頁、銷售分析及商品分攤依 `STOCK_REPORTING_SPEC.md` 繼續核對。成本帳尚未公開啟用，完整 I1–I12 與新安裝檔門檻仍保留。

## I12 實際交付門檻

先凍結目前參考成本的真實 native 基線。新流程須包含兩種進價、跨層出售、小數尾差、零及未知成本、部分到完整退回、預留取消恢復次序、未收款製作後取消、供應商折抵成本差額、盤點預留、舊資料開帳及遲補成本。所有量／值須守恆。

驗證 native／瀏覽器實際持久化、完整回覆檢查、空間不足、資料過期、不同認證角色、兩個實際 HTTPS 客戶端競爭、回覆遺失重啟、晚期回滾、超過 50 筆歷史、備份還原原編號、真實 2.16.0 舊寫入者正負控制。最後由新安裝檔實際解出的程式完成主要工作及重啟，並以真正關閉的 2.16.0 資料庫副本驗證升級；純模型通過不能替代此門檻。
