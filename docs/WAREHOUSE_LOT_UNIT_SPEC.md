# 存放地點、搬貨、批次與單位

完整 ERP 目標持續開發；所有店家、所有功能免費。本規格不縮減 `product-capabilities.json` 的 31 項公開義務。

## W1 日常操作

只有一個地點時沿用「店面」，不用先建立倉庫。收銀、顧客菜單、預訂、盤點與進貨沿用店面數量。另放在備貨區的商品不列入店面可售量；搬回店面後才可銷售。搬貨依序選商品、從哪裡搬到哪裡、數量，核對後確認「已搬好」。系統不替使用者假定實物已送達。

新增存放地點及商品包裝比例由店主核對；員工可在既有地點之間搬可用的貨。地點與單位有紀錄後不刪歷史、不由商品名稱猜比例。以後的改名、停用、在途及調撥核准須保留原文及核准紀錄。

## W2 同一份數量與成本

沿用 `stock_cost_entries`、`stock_cost_operations` 和 custody 的來源區間；不新增另一份可獨立更改的庫存餘額。`products.stock` 一直表示店面可售量，預訂數量另外保留。其他地點的可用量來自同一份 custody。調撥不能搬走已預留、已售、耗損或已退供應商的區間。

同一個 SQLite transaction／瀏覽器原子紀錄同時保存店面數量、來源地扣除、目的地增加、原編號回執及版本保護。搬貨保留來源 ID、數量區間、原 FIFO 次序與成本，不產生新進貨或損益。沒有成本的來源依然顯示待確認。只有新 `relocate` primitive 保留轉移次序，舊 `move` 的歷史重播結果不變。

## W3 明確換算

每個商品先有基礎單位。店主可設定「1 箱 = 12 個」等專屬比例；以十進位字串及整數最小量計算，最多三位小數。計算結果超出最小量、過大、為零、負值或缺比例時停止保存。確認畫面同時顯示輸入包裝數及換算後的基礎數量，比例改動後舊確認不能保存。

## W4 原編號與權限

送出前保存唯一操作編號。回覆遺失時核對同一筆，不能另搬一次；同編號改內容拒絕。先驗證目前使用者，再查原回執；已保存原單可在重開或還原後核對，新搬貨必須核對目前店面、還原 epoch、完整成本狀態摘要及時間。舊版不支援此功能時必須在寫入前停止，完整備份明列 `warehouse-v1`。

## W5 批次與效期仍屬必要範圍

接續須將供應商批號、到貨時間、效期連到原成本來源；未知批號或效期不得虛構。預留與出貨採 FEFO，過期隔離量不得出售。退貨須沿原單、原批與原成本區間，明確選可售、隔離或耗損。兩倉兩批、跨日到期、部分退貨、已預留的過期品、換機與原單復原必須走實際流程驗證。本輪先接通 W1–W4 的調撥與換算基礎，不能據此宣告 W5 或多倉批次義務完成。

## W6 驗證與公開界線

原生／共用店面／獨立瀏覽器：同一地點正常營業、兩倉轉出轉回、確切包裝換算、最後庫存競爭、員工與偽造呼叫、晚期 SQL／儲存失敗、回覆遺失後原單核對、完整備份與真正前一版寫入者拒絕。用 360px、四語、明亮與海報風格檢查實際畫面。成本正式啟用仍沿用原有開放條件，不由本功能繞過。真實裝置、老人兒童真人理解、尖峰營業、六控制正式資安與安裝檔更新分開驗收。
