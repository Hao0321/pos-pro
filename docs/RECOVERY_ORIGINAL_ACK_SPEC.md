# 已完成的復原，直接核對原結果

M16b，開發來源；完整 ERP、實體裝置與公開安裝檔另行驗收。

## A1 原結果先查

還原或找回資料前，先用原編號向目前權威查詢。已保存的完整原回執經既有協定、店面與原單關聯核對後，直接完成原畫面；不再次還原、不因現在預覽過期改開新編號。

找不到原結果才沿用既有確認與耐久編號保存流程。查詢失敗、格式不完整或原回執不符，保留待核對來源；不能把不確定當成沒做過。

## A2 各自核對，不清掉別人的紀錄

原結果已確認時，待核對紀錄若已由另一個畫面清除，不再誤報失敗。若目前保留的是不同編號、內容、店面或帳號的紀錄，原結果只完成自己的核對，保留另一份紀錄。

尚未提交或提交失敗時，只能處理自己的完整原紀錄；不能清掉不同或損壞的來源。現行畫面繼續使用既有共用交易鎖；任意不遵守鎖的舊寫入者與損壞資料保持獨立驗收，不宣稱任意競爭均已解決。

「核對上次復原」不能順便提交一筆查無已保存結果的收款、現金流水或其他交易。必須重新向目前權威查到該原編號的相符結果，才能完成其回執；其餘待核對來源保留，明確顯示「這筆已確認，還有紀錄待核對」。

## A3 證據

手機備份頁的設定分頁保持完整名稱與至少 48px 操作高度；切換較後面的分頁只捲動分頁列，整個設定頁不能跟著偏移。確認或取消對話框後，焦點接回但不挪動畫面。

先以實際 FileReader、原生 IPC 還原成功後、回覆到達前清除待核對紀錄，重現「已成功卻仍未確認」的 RED；一般成功為正控制。候選測原生與獨立瀏覽器的原結果、跨頁／重開、另一筆待核對紀錄、目前帳號、未知／偽造回執、查無結果及完整帳本。既有真正獨立來源的雙向完整備份、選檔、下載、原紀錄找回及配對 HTTPS 流程重跑。四語、雙風格、360px 與原始 31 項義務持續保留；這些測試不證明真人或正式六控制資安完成。
