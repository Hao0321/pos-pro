# 購物車與掛單

商品放進購物車後，會保存在目前裝置。重新開啟會接回原商品、價格、數量、會員、折讓與選填標籤。

- 按「先掛單」即可暫放；需要辨識客人時，可以先加標籤。
- 選擇掛單，再按「取回這張單」。若購物車已有商品，按鈕改為「先暫放，再取回」，系統會把目前這張保留下來。
- 同一張掛單只會由一個裝置成功取回。另一個裝置會看到原因，原購物車仍保留。
- 取消放在「其他操作」，並須再確認一次。
- 回覆不明時先「核對上次結果」。查不到才沿用原編號繼續；請勿重新建同一張單或再次收款。

掛單共用店面的既有掛單表；每個裝置的工作購物車依店面、還原世代與登入帳號分開保留。同一來源的兩個視窗透過 Web Lock 交接。手機必須連上店面 HTTPS，尚未完成的裝置購物車不會離線複製成另一家店的訂單。

正式保存使用 `pos-held-cart/v1`，在送出前保存固定操作編號與完整原內容。取單可在同一筆資料庫交易內暫放目前購物車、取回目標掛單並保存回執。回覆遺失後查詢原回執只讀取紀錄。掛單不改動庫存、營收、現金、點數或成本台帳。

收款沿用既有結帳協調器與原訂單編號。裝置另外保留該購物車對應的結帳計畫，避免全域暫存寫入失敗時產生新單號。已確認收款會保存空購物車的完成記號；清除暫存失敗後查詢原收據，也不會把已售商品放回購物車。較舊、未綁定購物車的收據不會清除另一張正在編輯的購物車。

可重現的隔離驗證：

```sh
npx vitest run tests/security/held-cart.test.jsx tests/security/store-flow.test.jsx
node scripts/run-native-security.cjs --held-cart
npm run build
node scripts/run-native-security.cjs --held-cart-ui
node scripts/run-native-security.cjs --held-cart-browser-ui
```

涵蓋原生 SQLite／preload／IPC、驗證身分的 HTTPS 共用店面、獨立瀏覽器、回覆遺失、原筆重試、雙裝置取單、換單、容量不足、後段回滾、結帳復原與四語兩風格的 360px 畫面。觸控主要操作至少 48px。

這是原始碼工作流程的改善。真人首次使用、實體手機信任與休眠、舊版程式對新掛單回執的完整相容性、公開安裝版與全系統安全驗收仍待完成；此階段不代表這些項目通過。
