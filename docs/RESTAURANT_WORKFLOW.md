# 正式預訂與出餐契約

本模組與收銀共用正式資料庫。所有店家免費使用，預設停用；老闆在「預訂出餐」確認每日／每 15 分鐘產能與配方後啟用。演練紀錄不匯入正式店面。

開發分支已將顧客桌碼原單接進同一份正式工作單，不必重新抄寫；桌號、品項、未收款金額與取餐號一起核對。操作見 [桌碼簡單指南](TABLE_ORDERING_GUIDE.md)，新增資料保護與驗收範圍見 [K1–K8](TABLE_KITCHEN_SPEC.md)。此改版尚未包含於既有 2.16.0 安裝檔。

## R1：接單與庫存

支援預訂、現場與外送，記錄日期、取餐時段、每日取餐號、聯絡方式與備註。取餐號由同一資料庫分配，取消也不重用。未設定配方的品項預留成品庫存；有配方的品項預留原料與包材，按庫存品項的單位計量。配方、價格、成本與預留明細隨訂單凍結。接單時一次檢查所有庫存與產能並扣除可用量；另一台手機不能再次使用已預留的最後一份。

## R2：製作與交付

`已預留 → 製作中 → 可取餐 → 已交付`；外送另有 `可取餐 → 配送中 → 已交付`。製作與收款分開，外送可出發後收款，但未收款不能完成交付。開始製作後取消仍占用當日與時段產能，原料不回補並列損耗；尚未製作的取消釋放庫存和產能。狀態異動必須帶原版本，拒絕覆蓋其他裝置的新狀態。

## R3：款項

每張預訂只全額收款一次，支援現金／刷卡／轉帳登記（轉帳使用非現金流水）。付款前必須開班；服務端從原單計算金額，保存既有收銀流水與原班別。收款回執包含交易編號、應收、找零及更新後的預訂版本。取消已收款訂單須老闆登入及目前開班，建立原流水的全額退款，退款計入實際退款班別。預訂退款由本模組處理，避免一般退貨把已耗用食材誤當成成品回補。本階段不提供部分預付或部分取消；有此需求先以完整訂單拆單。

## R4：回覆中斷與復原

所有異動先在操作裝置保存原操作編號，再提交一個原子命令。相同編號與內容可重試並讀回目前庫存；改內容重試拒絕。未收到完整回執保持待確認，不能建立另一筆收款。備份包含預訂、配方設定與操作回執；損壞或缺少關聯流水的還原整批回滾。手機斷線停止寫入，恢復後仍使用原操作編號。

已製作取消的損耗按凍結的每單位成本與數量計算，加入損益表；退款沖回銷售後仍保留實際損失。已扣庫、入帳的損耗紀錄須保留，更正使用盤點與會計異動。預訂模式的完整資料目前請使用 JSON 備份；既有雲端快照缺少預訂／回執時會拒絕同步，手機共用店面不受此限制。

## R5：驗收

以隔離資料庫量測正常接單、相同／改內容重試、並行最後庫存與時段、版本衝突、收款找零、交班、製作前後取消、全額退款、跨班退款、觸發器中途失敗及備份／重啟。正式 Electron 與手機尺寸共用 HTTPS 須實際操作接單、收款與出餐，確認保存回覆之前不顯示完成。實體手機的憑證信任、休眠與相機／印表機須獨立實機驗收。
