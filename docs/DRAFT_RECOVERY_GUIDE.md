# 還沒送出的內容會保留

在「預訂出餐」設定菜單、配方與產能、選餐點或新增一般預訂時，這台裝置會自動保留草稿。離開畫面或重新開啟後，可接回原輸入。未填完的價格、份數、用量及聯絡方式也會保留；接回餐點後仍需重新核對價格與庫存，再確認送出。

同一個帳號在另一個視窗編輯同一份草稿時，這裡會等候。離開原視窗的該頁後，另一個視窗會接回最新內容。不同裝置保留各自的草稿；確認送出的訂單仍共用同一間店的紀錄。

若菜單被其他人修改，按「保留輸入，重新核對」。系統會合併不同欄位的修改；同一欄位若衝突，先保留輸入，請核對目前店內設定。

配方與產能有衝突時，會列出「我填的」和「店內最新」。選好要保留的值後，再按「儲存預訂設定」。核對及選值本身都不會修改正式設定；新菜單、桌碼和廚房設定也會保留。

保存後若回覆中斷，原編號仍會保留。重開原畫面時，系統會先向店面核對已保存的來源與完整回執，再完成原畫面，不會自行另開新單。

同一份採購再貼一次，若已建立，會顯示原金額。「查看單據」直接開原單，不會再叫一次貨；內容有變更時會保留輸入，請先核對。

換帳號、換店或還原備份後，先前範圍的草稿不會自動套入。若本機草稿讀不到，可先「下載原草稿」保留原檔，再選「清除這張未完成草稿」；這只處理草稿，不會刪除商品、正式訂單或帳務。

舊版快速草稿接回時，會先保留原內容，再找已建立的原單；已接受的過期報價不必重開程式。內容不同或查詢失敗時，原草稿仍保留。

顧客掃碼頁也會在這個瀏覽器保留未送出的購物車、未選完的加料與原始姓名備註。同一瀏覽器的另一個分頁會等候原頁離開後接手；已送出而尚未核對的內容先走原單核對，不另開新單。不同桌碼、店面或正式還原世代不會互相帶入草稿。異常時可下載保留資料，再明確選擇是否清除這份未送出的點餐。

菜單遇到同一欄被兩邊修改時，直接選「保留我填的」或「用店內最新」，尚未套用的選擇也會保留。重新開啟時會再向店面核對；資料又變更時需重選。用量與單位一起處理，套用後仍要另外預覽、確認保存。[菜單選擇規格](MENU_CONFLICT_CHOICES_SPEC.md)另有說明。

這是開發分支的菜單設定、配方與產能、店員餐點、一般預訂、顧客點餐與快速建單草稿功能。[快速建單](QUICK_DRAFT_RECOVERY_SPEC.md)、[一般預訂](ORDINARY_ORDER_DRAFT_SPEC.md)、[配方與產能](RESTAURANT_SETTINGS_DRAFT_SPEC.md)及[顧客點餐](CUSTOMER_CART_RECOVERY_SPEC.md)另有說明。完整 ERP、實體裝置和真人驗收仍待接續完成；既有安裝檔尚未包含本次改版。
