# 第一個情境模板：丼飯外帶

本輪方向為一般豬／牛丼飯與冬瓜茶，預訂和現場都要，也保留外送。所有店家、全部功能免費。菜單與份量可依自己的試賣調整；示範設定不代表已測得的出餐容量或正式售價。

## 已接上現有 POS

管理員從「情境模板 → 套用菜單」填每個品項的售價、單份食材／包材成本與目前可售成品數量，再新增豬肉丼、牛肉丼和冬瓜茶。成本尚未知道時先使用演練，不把空白自動當成零。

三個商品與套用回執一起保存；桌面使用 SQLite transaction，瀏覽器使用原本的單筆原子紀錄與交易鎖。重試相同操作不重加商品、不重設賣掉的庫存；編號衝突或保存失敗保留原資料。桌面在已驗證主視窗／角色檢查後才允許管理員套用。套用回執寫入稽核資料，包含在完整備份內。

既有商品、帳號與交易保留。現階段可用原有收銀、成品庫存、班別、備份與報表；套餐先將丼飯及冬瓜茶一起加入購物車。

## 可以操作的試賣演練

「情境模板 → 試賣演練」包含：

- 預訂／現場、取餐時段、稱呼及備註；外送另記電話與地址。
- 每日及時段碗數上限，預訂與現場共用原料預留。
- 已開煮後取消仍占用產能；尚未開煮取消才釋放每日與時段名額。
- 待備餐、製作中、可取餐、外送中、已交付；付款狀態獨立核對。
- 接單預留、開煮扣料一次；取消後釋放未煮原料，已開煮原料作耗用／損耗。
- 付款與退款人工確認、穩定操作編號、已付款取消及重複操作檢查。
- 依取餐時段分批備餐、原料及包材換算、起始配方調整。
- 進價空白保留未知，開煮時保存成本快照，已收款與已交付收入分開。
- 示範紀錄保存、重開與 JSON 匯出，390px 手機版面及桌面版面。
- 紀錄損壞時保留原始資料並可匯出，拒絕繼續覆寫；完整核對單號、金額、原料、收款及出餐狀態。

演練使用獨立本機紀錄，不寫入正式商品、交易或原料庫存。桌面演練 iframe 不提供 native bridge。它不能代替正式網路接單、庫存權威、備份遷移、金流或真實硬體／新手驗收。

## 正式預訂與出餐

2.7.0 的「預訂出餐」已接入正式資料庫，支援預訂、現場與外送登記，並與手機共用店面使用同一個庫存權威。老闆先確認每日／每 15 分鐘產能，在庫存管理建立原料與包材，再設定每份配方。按商品庫存的單位填寫用量；例如使用公斤作單位時，90 克應填 0.09。

接單時預留原料與包材；沒有配方則預留成品。收款不再重扣，未製作取消可釋放；已製作取消保留耗用、產能與損耗費用。每天的取餐號不因取消重用。價格與成本隨單凍結，款項、取消退款、操作回執與所有設定可完整備份。契約與限制見 [正式流程](RESTAURANT_WORKFLOW.md)。

有配方的餐點請走「預訂出餐 → 現場」接單，不要另外把同一批原料再登記為可售成品。顧客自助網路預訂、LINE 自動接單、加料組合與外送平台整合仍在後續規劃。

情境模板使用 `electron/scenario-templates.json` 登記，共用同一套輸入驗證與原子套用服務；新增店型沿用此接口。範本不建立收費等級，也不把只有演練的能力標成已正式支援。

舊的 2.6.1 安裝檔沒有以上模組；請核對 [2.7.0 安裝說明](INSTALLER_2_7_0.md)。
