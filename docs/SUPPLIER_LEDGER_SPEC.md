# 採購核准、供應商預付款與跨單抵付

此文件定義 2.16.0 供應商帳本的實作與交付驗收要求；安裝檔須通過 S8 與對應建置收據。完整 ERP 的原始 31 項目標維持不變；所有店家、全部功能免費。

## S1 預設簡單，需要時才核准

預設由一位管理員建立採購及記錄實際付款，不增加例行核准步驟。可選「另一管理員帳號核准」；啟用前須有至少兩個管理員帳號。新採購與預付款提案會凍結當時模式、送審帳號及內容；另一個經後端認證的管理員才能核准，不接受表單自填核准人。此為帳號間的工作流程，不認證帳號背後是否為不同自然人，也不取代資料庫管理或實際銀行授權。

模式變更須明確確認並留理由，只影響之後的新提案。已送審文件的核准要求不因切回簡單模式消失。核准、退回、撤回均留原紀錄；未核准或已退回的採購不能收貨、請款或付款。尚未交易的採購可依原規則取消，不能刪掉核准歷史或直接改價改量。舊採購不補造過去的核准人；需要納入核准時明確登記本次送審，保留既有歷史。

## S2 記錄實際付出的預付款

以既有固定供應商代碼識別，不以同名合併。可先於採購、收貨及請款記錄預付款；確認實際付出後保存一筆原付款與回執。現金連結目前班次並原子記錄支出；銀行只記錄已核對事實，不觸發轉帳。名稱修改不改寫舊單或舊付款的名稱。

核准模式下，先送出供應商、金額、方式與說明提案，另一管理員核准後，才能明確確認實際付款。送審與核准都不產生現金或存貨。已核准提案只能用一次，不能換供應商、改金額或方式後挪用；結果未知須沿用原操作編號。供應商預付可以不指定採購單，保留為該供應商可用額，日後再抵付。

## S3 一筆原付款抵付多張請款

在同一供應商內選取多張已核對的請款，逐張顯示本次金額、合計及剩餘預付額。可按到期日建議分配，仍須人工核對。權威端檢查供應商、採購版本、核准狀態、請款餘額及原付款可用額，禁止超額、重複請款列及跨供應商搬款。

抵付不再產生現金支出或存貨。原採購逐單付款須扣除已有抵付，不能重複付款；每次受控採購及預付款操作核對供應商帳版本。歷史同時驗證採購所見帳版本與抵付所引用採購版本，不能只檢查現在的總額。

## S4 解除、退回及更正

部分或全部解除原抵付需理由，款項回到原付款可用額，不表示供應商已退錢。收到供應商退回的未使用預付款，須引用原付款、確認實際收到、金額不超過可退額，並沿用原現金／銀行方式。退款更正及整筆付款更正另留引用與理由；原付款已有有效抵付或退款時，先處理相關紀錄。

已交貨退回或折抵造成多付時，原逐單付款及預付抵付分開追溯。逐單退款不能使用另一筆預付款的餘額；預付部分先解除抵付，再從原付款記錄實際收回。不刪改已過帳紀錄，不把帳面可退額顯示成現金已收回。

## S5 帳務來源

預付：借 1261「供應商預付款」、貸 1101 現金／1103 銀行；抵付已核對請款：借 2101 應付帳款、貸 1261。解除方向相反；供應商退回預付款借現金／銀行、貸 1261，更正則反向。收貨、請款及退貨仍沿用原採購來源，不因預付重複認列存貨或費用。

以 TWD、整數分記帳，不猜匯率、稅額、利息或跨公司關係。設計參考 [IAS 2 的存貨成本及費用認列說明](https://www.ifrs.org/issued-standards/list-of-standards/ias-2-inventories/)。長期融資、減損、稅務及完整財務關帳仍屬其他待完成能力，不宣稱本流程是 IFRS 認證。

## S6 不可改寫的回執與相容性

`supplierEntries`、`supplierOperations` 分別保存不可改寫事件與正式回執；採購登記核准需求與原採購建立須在同一交易提交。預付款、現金流水與回執也須原子提交。重送原編號先查原結果，再檢查新操作的時效或版本；回覆不完整時保留原編號與鎖定草稿。

原採購文件不因外部抵付被改寫，因此新增持久的功能寫入柵欄，阻擋不支援供應商帳或核准要求的舊連線繼續收貨付款。瀏覽器完整集合也須拒絕不相容舊版。SQLite、JSON、瀏覽器原子紀錄、共用店面、雲端拒絕覆蓋、還原保護前像及原編號索引都包含新集合；舊備份缺集合可讀為空，覆蓋前仍保護目前完整帳本。

## S7 使用者與 Agent 流程

入口以「供應商與預付款」呈現，先選供應商，再看「已付訂金」「抵付請款」「收到退回款」。待核准採購及付款提案顯示送審人、原內容、下一步；同帳號不能核准自己的提案。簡單模式不顯示多餘的企業流程。明亮／海報、四語及 360px 都保持可操作，未保存輸入與原編號草稿可恢復，歷史可查看較早紀錄。

Agent 使用獨立的版本化供應商付款草稿，只填供應商、金額、方式及參考文字。系統先帶入核對，依目前模式送審或由管理員確認已實際付款；不接受 Agent 自填核准人、已付款確認、憑證或執行指令，不自動轉帳。原本 POS 購物車、採購及客戶收款協議保持原意。

## S8 實際驗收

同名供應商分開；付款先於收貨；一筆預付抵付兩張不同採購請款；部分解除、收到退款、更正、混用逐單付款與退貨；1261／2101／現金銀行及存貨不重複。核准涵蓋預設簡單、啟用、不同帳號、同帳號拒絕、偽造角色、資料過期、已核准提案一次使用，以及模式變更不放行既有待核准。

驗證兩個實際 HTTPS 裝置競爭、提交後遺失回覆與重啟、晚期 SQL 失敗完整回滾、瀏覽器空間不足、偽造回覆、失效身份、超過畫面筆數的歷史、完整備份還原後原編號防重送及舊程式寫入拒絕。最後使用安裝檔中實際解出的程式完成主要流程與重啟；來源測試、實體設備、母語校對及真人易用性分開記錄。
