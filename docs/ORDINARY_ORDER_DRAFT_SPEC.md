# 一般預訂草稿

在預訂出餐的「其他商品」或尚未設定菜單時，原始顧客、聯絡方式、日期、備註及尚未輸完的份數會保留。不同帳號、角色、店家及還原世代分開；兩個視窗不會靜默覆蓋。

一般手動表單沿用既有 ordinary Agent 的核對與提交協議。確認前檢查真正的店面、配方、產能、庫存和使用者權限；新價格與畫面不一致時先保留輸入，按重新核對看清楚後再確認。未確認不會預留、收款或新增正式訂單。

送出前保留實際請求與原編號。回覆中斷或已在另一頁核對時，先驗證原始內容及完整回執，再結束原畫面。查詢與還原期間的舊回覆不得清掉新世代草稿。

接回舊版快速草稿時，先把原內容保存到目前範圍，再查已建立的原單；已接受的過期報價不必重開才能找回。核對失敗保留兩份原內容；只有成功接回或完成原單才退休仍相同的舊快取。

本規格不宣稱原始 Agent JSON 的歷史欄位可以回填。原價／原單證據層級遵循 QUICK_ORIGINAL_IMPORT_SPEC.md。產能／配方設定的未送出修改、顧客購物車、完整 ERP、正式資安六控制、真人與實體裝置仍另行完成。
