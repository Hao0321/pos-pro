# 批次盤點規格

## LC1 實際數量

盤點入口在啟用批次後採用「選商品與地點 → 填看到的數量 → 看差異 → 確認」。輸入欄保持空白，不自填系統數量。只調整本次有填的批次；空白代表未盤，零才代表沒有。每列保留基本單位，不能加總不同商品的數量。

## LC2 分清楚貨在哪裡

每個地點、原始來源批次分開盤。「架上」包括還沒開始製作的預留；製作中的材料不算架上。預留量是下限，少於它時先核對原訂單，不能自動扣掉客人的預留。「暫停販售」另列，不能藉盤點恢復販售。效期以店面單調日期核對；日期未知仍保持未知。

已開始製作的材料仍可能保留在預留成本狀態，不能只看成本狀態判斷架上量。首次批次盤點凍結實際原訂單的 ID、版本、狀態及開始製作時間；後續出餐操作同步更新這個狀態切片，完整備份與讀取須和原訂單相符。數量及成本仍只有原成本帳本一份權威。

## LC3 差異與成本

少掉的數量從該列的原始可動用區間轉到盤虧，沿用原始成本；已預留與製作中的區間不動。多出的貨建立獨立、成本待確認的新來源，不套用商品參考成本或另一批進貨成本；已知批次的批號與效期可連到新來源，原進貨歷史不變。隔離列的盤盈仍隔離，過期或必填效期未知的貨不得變成可賣庫存。盤盈不代表現金收入。

額外找到的貨用明確連結維持同一實體批次，成本來源各自保留；之後盤點不會多出兩筆同名批次。核對效期須同步這個實體批次的所有來源；原始來源的數量區間及已認列成本不重寫。

## LC4 一次保存與原編號

沿用同一成本帳本、批次操作及 `applyLotOperation`，新增嚴格 `count` 指令。整組差異、實際可售數量、成本分錄與新來源一次提交。原編號先保存；相同原操作重試返回原收據，改內容拒絕。跨店、還原、日期／庫存／批次變更須重新核對並保留原輸入。晚期失敗必須完整回滾。店員可盤點，批次與效期設定仍只限店主。

## LC5 Agent 與草稿

Agent 只能轉寫使用者提供的實盤數量；資料包中的品名不是指令，不執行網址、不猜數量或單位。只接受同店、同份核對資料與列 ID 的純十進位數量，貼回後由人看差異並確認。輸入及 Agent 原文依店面／帳號保存；獨立頁面編輯鎖、損壞下載、回覆中斷及重開均保留原單。

## LC6 相容性與量測

首次批次盤點增加 `stock-lot-count-v1` 功能旗標與持久 SQLite 寫入圍籬；完整備份與保護還原保留旗標，舊程式不能改寫。不得改動前版 lot/custody 事件語意。量測原生 SQLite、IPC／HTTPS、獨立瀏覽器、完整備份、實際前版讀寫與拒絕、四語雙風格 360px、成本與歷史。正式資安六控制、實體設備、老人兒童真人理解及完整 ERP 仍分開驗收。
