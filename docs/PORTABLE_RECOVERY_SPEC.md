# 完整備份與換機找回

此規格補充 [備份與找回](STOCK_RECOVERY_SPEC.md)、[庫存成本](INVENTORY_COST_SPEC.md)、[成本試算](COST_PRICING_SPEC.md) 與 [報表](STOCK_REPORTING_SPEC.md)，保留原始 31 項 ERP 的全部要求。基線為 `4c5d394`：目前業務與成本集合可完整備份，但獨立保護副本、原編號索引與復原回執不在外部 JSON 中；換機後可能無法判斷原交易已保存。前一輪是已驗證的 progress，並非完整 ERP 交付。

## B1 明確的完整格式

新的完整備份標示版本、來源儲存格式、店面、當前業務帳、保護來源與整份校驗。缺少任何必要部分、未知版本、損壞或只剩半份時拒絕並保留原檔，不猜成空資料。真正舊格式仍可核對匯入，但明示其不含完整保護紀錄；診斷檔不得當一般備份。完整格式的校驗只證明內容一致，不冒充來源認證或數位簽章。

保留原生與獨立瀏覽器現有不同格式，標示來源並驗證同格式異機完整恢復。未經可驗證轉換的跨格式匯入須拒絕，不能猜欄位或丟保護資料；跨格式互通仍保留為後續目標，不因同格式驗證通過宣稱全產品完成。配對手機繼續使用原生權威。

## B2 平面來源與完整索引

保護資料以內容定址的原始帳本、來源紀錄、原編號索引及復原回執平面保存。相同內容只存一份；來源只參照帳本，帳本不得再包含完整備份或另一份保護圖。必須保留每份原始內容、來源編號、店面、時間、操作者、原校驗及還原後邊界。所有索引逐筆對得上來源實際原操作，缺少、重複、懸空與額外索引都拒絕；不能以重新猜索引掩蓋缺失。

## B3 原紀錄合併

匯入保護來源與本機原來源合併，同編號同內容去重，同編號不同內容拒絕，不覆寫原回執。每次再次匯出或還原只新增該次必要的保護紀錄，大小隨實際來源增加，不遞迴包入歷代備份。所有來源、索引及回執跨過顯示上限，不能只保存頁面可見紀錄。來源原店面、目前店面及復原目標分開核對，其他店的保護資料不會取得自動覆蓋資格。

## B4 逐份驗證

先驗整份格式與校驗，再核對每份原帳的內容校驗、成本鏈、原業務、數量保管及來源店面；驗證保護圖完整性與復原回執的原編號、簽章資料和來源連結。缺資料與未知成本不能轉成零。原生原始 JSON 及瀏覽器原內容簽章保持原樣；不能為了換機把原成本事件、日期、金額或歷史回執重寫。

## B5 目前登入與歷史操作者

只有真正登入的店主可匯出或匯入完整保護資料。換機保留目前帳號、密碼與連線憑證；備份中的角色或舊密碼不授權登入或升權。已驗證店主可核對舊操作者的完全相同原回執，這是查詢歷史，不以舊身分執行新交易；店員或偽造帳號不能用此方式讀取私帳或開新成本帳。新操作繼續用目前實際操作者。

## B6 原子還原與時效

預覽綁定當前業務與保護資料的版本及完整匯入內容，兩者任何變動都使舊預覽失效。確認時在同一原子提交保存當前完整保護前像、合併來源／索引／回執、替換業務與成本、旋轉執行期及保存最終回執。晚期失敗、容量不足、衝突或來源錯誤時全部回滾。重送同編號只回原回執；換機後原交易仍不明時不能重新收付款或開帳。

已知的純相容性標記與無新內容的格式補齊不應被誤認為新營運資料；舊來源邊界不改寫，僅接受可逐項證明等價的版本差異，不泛化忽略實際金額、數量、價格或營運設定。

## B7 一份檔案與簡短核對

沿用「匯出備份 → 新裝置匯入 → 看重點 → 確認」流程，不要求使用者理解圖、索引或回執格式。核對先列有變動的四種紀錄，其餘折疊；若更多項有變動須在折疊標題明示。完整保護來源數與舊格式缺口可在核對中看清楚。備份頁可按日期找回還原前副本，不依賴舊裝置的待確認暫存；有新營運資料或其他店面的副本不可直接覆蓋。少字、大按鈕、四語、兩種風格及 360px 保持可操作；必要的確認不跳過。真正長輩、兒童與母語者的易用性驗收另行保留。

## B8 真實驗證

先以基線實際 SQLite 證明：同裝置原紀錄可找回，匯出後新裝置卻失去原編號柵欄。再用相同來源驗證完整檔案轉移、重新開啟、原回執查詢、原帳找回、反覆去重及所有金流／成本只保存一次。包含原生、獨立瀏覽器、真正 FileReader／下載資料與登入 IPC／配對 HTTPS；比較全部業務、保護圖、索引、憑證、執行期與回執，並驗證衝突、改內容、缺節點、缺索引、過期、偽造／店員與晚期回滾。來源實作不能替代精確新安裝檔、真正舊版升級、實體裝置、真人、規模及完整 ERP 驗收。
