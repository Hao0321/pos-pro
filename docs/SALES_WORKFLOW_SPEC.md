# 企業銷售與應收：實作規格

狀態：已接通來源程式、原生畫面及私人共用店面；交付與全回歸驗證進行中。全 ERP 的 31 項範圍維持不變，所有功能免費。一般操作見 [接單、交貨、收款](SALES_GUIDE.md)。

## S1 操作與身份

管理員選客戶、確認商品、數量與議定單價，建立「已接單、尚未備貨」的銷售單。可由本店已保存且有效的客戶專屬報價帶入，固定原報價版本、收件客戶及計價快照；同一報價家族不能重複轉單。手動建立填客戶名稱，系統先產生並明示可修改的獨立客戶代碼，也可選原往來客戶。不以同名自動合併身份、不假冒會員、不自動產生點數或修改會員餘額。

建單不扣貨、不收款、不認列收入，也不表示已保留庫存。交付時檢查同一個權威資料庫的實際可用量；不足就整筆拒絕。獨立的庫存分配／實體庫存與預留分離仍屬完整 ERP 待完成項，不以此里程碑代替。

## S2 交付與請款

按「這批貨已交給客戶」，輸入本次數量與收款到期日，確認這批貨已依雙方條件完成交付、取得請款權利。這個操作建立不可改寫的交付及內部請款紀錄，原子扣庫存並保存當次成本。不是物流發車記錄或正式稅務發票。

使用者確認的交付是本流程的記帳點，收款則沖減應收，不重複記營收。設計參考 [IFRS 15 的控制移轉原則](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-15-revenue-from-contracts-with-customers/)；本實作不代表符合所有合約情形、法域稅制或 IFRS 認證。

數量最多三位小數、單價兩位；各批交付依同一訂購列的累積數量計算差額，最後一批取回尾差。每次交付保存原始商品單位及成本，不從後來改價重算歷史。成本依現有商品成本欄位快照，不宣稱 FIFO／加權平均成本政策已完成。

## S3 收款與更正

每筆收款對應一張內部交付請款，可部分收款，不能超過未收餘額。現金必須在目前開啟的班次，原子建立現金流入；銀行收款僅登記使用者已確認的收款，不呼叫支付商或銀行。

錯誤收款只能以理由建立全額更正，保留原紀錄並沖回同一張請款及現金／銀行；已有有效退款的收款必須先更正退款。退款更正另留原退款引用。不可直接覆寫或刪除已過帳文件。預收款與一次核銷多張單仍需後續實作，不把未交貨款當作銷售收入。

## S4 退貨、折讓與退款

退貨引用原交付，累計不能超過原交付量。選「可再銷售，放回庫存」才原子加回庫存並沖回原始成本；不可再銷售的退回不加庫存，保留已發生成本，避免另寫一筆損耗而重複認列。

折讓引用原交付、理由與金額，不能超過尚未折抵的請款金額。已折讓金額與退貨不可把同一價款重複退回；無法唯一核對時要求先分開處理或更正。

退款必須引用原收款，不能超過該請款的實際多收餘額或原收款尚可退金額。付款方式沿用原收款；現金退款／更正都要目前班次。全部收款、退款、沖銷各有獨立原編號。

## S5 權威、復原與整合

銷售單、交付、款項與原始操作回執存於同一資料庫；非連線副本。每次請求先保存原編號，資料版本及店面身份在權威端驗證。同一編號重送查回原文件；不同內容拒絕。未知歷史不可當作未提交重新建單。

建立人與每次操作人取自已驗證的管理員身份，保留當時的帳號 ID 與名稱；不接受表單自填操作人。後續操作日期不得早於本單既有紀錄。完整還原會在同一原子提交中更換本機還原識別，識別不進入可還原的商務快照；找不到原回執的舊操作須保留待核對。

JSON 備份、SQLite 升級、瀏覽器原子紀錄、共用店面、現金交班、總帳與報表必須保留完整來源與不重複認列。UI 顯示筆數限制不能刪正式回執。尚未接妥的整合不得呈現為已完成。

畫面沿用明亮／海報風格與四語系：客戶／議定條件是商家資料，介面翻譯不改它；48px 操作與目前下一步優先，未確認保存時保留原表單與重試。
