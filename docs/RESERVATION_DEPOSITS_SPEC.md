# 訂位訂金與餐點抵款

狀態：M19 開發中。完整 ERP、全部店家免費、極簡建單與會員福利目標維持原範圍。此規格不是已上線、零 Bug 或完整訂金功能的聲明。

## DP1 店家的操作

老闆以「不收訂金／每桌／每人」起步，設定金額即可；指定日期、星期、餐期、人數與來源收在進階規則。客人看見實際適用金額、幣別、條件版本及收款方式。訂位成功、記錄實收、餐點抵款及退款完成是不同事實。沒有串接金流時，現金與銀行紀錄必須明確表示是店員核對後登記，不能宣稱已刷卡或已匯款。

接待卡顯示應收訂金、實收、已抵餐點、已退款及剩餘可用。店員核對真正收到的金額後保存；金額與客人、原訂位自動帶入。點餐確認時自動建議抵可用訂金，顯示剩餘餐費；超過餐費的餘額仍屬於客人，不能變成折扣、額外收入或不見。分開點餐與追加餐點共用同一原收款上限。

取消訂位、未到店或減少餐點不代表已把錢退回。接待保留待退／待核對金額及一個明確的退款入口。外部金流、LINE、簡訊與自動失約扣款未接通前保持未驗收，不推定任何對外付款。

## DP2 條件與版本

條件使用店面日期與時區；跨午夜餐期按餐期起始日判斷星期與日期範圍。進階規則依顯示順序第一個符合者生效；順序、規則 ID 與範本均屬版本內容。所有金額用整數分計算，乘人數與加總檢查上限，不用浮點數估算。

每筆訂位保留當時的完整訂金條件摘要、政策版本及指紋。修改店家政策只影響新訂位；候位轉成正式訂位時才保留適用條件。改期與人數修改不得靜默改寫已確認條件；若要重新報價，需呈現原條件與新金額再確認。首版採未使用訂金全額可退，不實作沒收、罰款或自動扣款。

正數訂金必須由呼叫者帶入實際核對的`depositQuoteHash`；後端不可自行補上。未帶指紋、指紋已過期或條件不同的舊畫面不能悄悄建立附帶訂金的訂位。既有未啟用訂金的店面沿用原協議；新條件畫面及餐點抵款完成前，訂金收款入口保持未開放。

## DP3 錢與原來源

收款沿用既有現金流水、班次與會計權威；預收借現金或銀行、貸餐飲預收款2193。實際交付餐點時才由既有餐飲交付認列收入；訂金抵餐費是同一預收來源的轉用，不能再次收現金或再記一筆銀行收入。抵款與解除抵款必須連到真實餐飲原單、資金事件與訂位，不使用虛構商品、儲值會員或假管理員。

現金以本次開啟班次記錄淨實收或淨退款；找零不增加收入。銀行登記不放現金班次。每次退款引用原收款，不能超過未抵用且未退的來源餘額；解除餐點抵款需先確認餐飲退款事件，不能只改訂金餘額。混合來源保留原來源分攤，退款不能把銀行款當現金退或超退。

## DP4 共同保存與恢復

每個動作在送出前保存原編號、店面、還原世代、訂位版本及完整輸入。原生同一SQLite transaction、瀏覽器同一把既有業務鎖與同一筆紀錄保存訂位、收退款、班次、餐飲資金與回執。晚期失敗全部回滾；提交後失去回應或重開，查回同一原編號，不能重新收款。

新版持久化格式為18，使用獨立的`reservation-deposits-v1`能力及`reservationDepositVersionFence`。真正前版17的暖／冷啟動要拒絕不支援的店面。完整備份、跨儲存轉換與非回滾原單保護包含政策、原收款、抵款及退款；還原較舊備份若缺少已知款項，暫停新的業務異動，要求完整復原，不能用零餘額取代未知款項。

## DP5 開發次序與驗收

1. 共用條件與收退款計算器：真實政策版本、每人乘算、跨日規則、分次實收、來源退款及平衡分錄。
2. 正式原生／瀏覽器保存與完整備份：實際流水、開班、權限、原編號重試、晚期回滾、原版17及舊備份保護。
3. 正式餐飲抵款與退款接續：同一預收來源抵真實餐費；兩裝置競爭不能多抵；部分取消、已交付退款與追加餐點不超原來源。
4. 極簡店主設定、接待、免登入客人確認與手機流程：四語、兩種風格、360px及觸控操作；以真正老人、小孩及首次使用者另驗收。

必須完成以上共同流程才可把訂金收款入口交給店家使用。只完成計算器或後端不得宣稱整個訂金功能可用；所有未完成項目留在同一完整ERP目標內，不能用測試數替代。

## DP6 訂金抵餐費接續（M20 開發規格）

已公開的格式18保存條件、實收與原來源退款。新增抵餐費與退回訂金的歷史使用格式19及獨立的`reservation-deposit-application-v1`保護；真正的格式18程式必須拒絕不支援的新資料。此段描述待完成的共同流程，不表示格式19或操作畫面已經可用。

每次抵用先從同一訂位的實收原單依保存順序選來源，抵用上限是原來源未退未抵的餘額與餐飲未付金額的較小值。檢視結果保留店面／還原世代、訂位版本、真實餐單與版本、原收款、條件指紋、抵用金額及剩餘餐費。店員確認餐點的同一動作同時確認這份抵用結果；資料改變時保留原選項，重新顯示結果，不能靜默改價或多抵。

原餐單、餐飲資金抵用事件、訂位抵用回執、庫存成本、廚房與復原保護一起保存。抵用事件引用原收款及實際現金／銀行來源，但不新增現金流水、不新增收付分錄、不觸發會員儲值或點數。餐點交付仍由既有餐飲預收款2193認列收入；餐費不足的部分沿用正常收款。金額超過餐費的訂金保留給客人。

部分或全部餐點取消後，退回訂金來源的份額必須對到真實餐飲退回事件與當初抵用明細。畫面清楚區分「留作訂金」與「實際退款」；前者只恢復原訂金可用餘額，後者還要由原收款方式登記真正退回的金額。現金退款使用目前班次、銀行來源不能當現金退；未串金流時不宣稱已執行銀行或刷卡退款。新流程不得把不明退款意圖自行補成已退錢。

正常餐飲入口不能自行製造訂金來源；內部共同保存必須核對原訂位、實際餐單、付款來源及完整輸入。兩裝置、分開點餐、追加餐點、取消重點與原編號重試共用同一可用上限。任何遺失原收款、抵用或退回承諾的還原都保留未知狀態並暫停新業務異動，要求完整復原。既有無訂金或無抵用的格式18歷史仍需原樣重播。

實際退款由原餐飲取消編號產生固定的訂位退回編號，再按原收款編號合併為固定的退款編號。餐飲退回、訂位釋放、每筆實際退款及現金班次紀錄一起保存；退款意圖不能只保存釋放紀錄。回覆只附一份最終訂位狀態及各原單回執，缺少任一實際退款回執時保留原待確認紀錄。完整復原後沿用舊編號核對，不能因還原世代改變再執行一次退款。

點餐畫面從原訂位讀取實際可用來源，顯示「訂金抵用」與「餐點還要收」，超出的部分顯示剩餘訂金。草稿保留當時來源；另一裝置改變餘額或條件時，保留餐點並要求重新核對。取消表單只在選定份額真正涉及訂金時顯示「留作訂金／已退回客人」，不預設已退款；純轉帳退款不製造現金班次。這些畫面通過也不代表可啟用收款入口。

## DP7 公開條件與完整收款入口（持續實作）

啟用店主訂金設定、接待收款與公開訂位入口前，必須完成同一條客人流程：公開網站顯示該日期、時段與人數的實際訂金及取消條件，客人明確接受條件後才成立原訂位；訂位確認不表示已付款。店家由原訂位核對實際現金或轉帳收入，支援部分收款、現金找零與原來源退款，金額自動換算為整數分，不讓使用者手算。

先沿用目前已存在的`depositQuoteHash`、公開建單v1與原訂位凍結條件；桌面手動建單、候補轉正與網站都核對同一份條件。先以真實格式19開發副本驗證可重播，不因缺少畫面就另造平行協議。若確實新增舊版不懂的請求欄位或歷史語意，才先安裝獨立版本保護，再寫入新歷史；保留1164檔前版副本作為控制。不得把接受條件藏進備註或借用付款旗標。舊公開原單可依原編號唯讀查回；未成立的新單遇到條件改變須保留輸入、重新顯示條件並再次同意。未知結果不能重建編號或當作未付款而重新收款。

店主設定、接待表單與網站草稿沿用既有原編號、權限與共同交易，不另設餘額資料庫或以登入會員代替店主授權。手機及電腦共用一個權威；取消、收退款、回覆遺失、完整復原與前版保護全部通過後才開放收款入口。簡單明亮／海報風格、四語系、360px、真人與實機驗收仍屬完整ERP目標。

客人離席、訂位取消或所有餐點結束後，仍有未用訂金時，畫面及跨日期待處理清單必須明確保留這項責任，提供原訂位的核對入口；不能以「餐費已收齊」把未用訂金隱藏，也不能自動當成會員儲值、收入或已退款。改期與改人數時明示沿用的原條件；需要重新議定條件時另以有證據的同意流程處理，不能靜默改寫舊條件。

目前本機開發版已接上公開網站的實際報價與明確同意、店員手動訂位及候位轉正的條件確認，以及離席／取消後的未用訂金清單。選好時間就收起時段表；改選時間清除舊同意。店員異動草稿依店面、帳號、訂位與動作分開保留；尚未確認原結果時只核對原條件及原編號，不混入新價格的同意流程。公開私人回執只顯示原條件與自己的實收／抵用／未用／退款合計，不傳送原收款編號、銀行參考資料或其他客人的資料。

本機候選版另提供店主政策設定、接待現金／銀行實收及原來源退款表單。店主保留既有特殊規則，只調整新訂位的預設條件；首次準備餐點收款沿用既有正式設定交易，不修改歷史餐單為已付款。收款自動帶入可收額與找零，退款依實際退回的原收款方式與上限登記；銀行操作仍由店家完成，系統不代為轉帳。

收退款草稿保留少量摘要、來源指紋與原編號，不把全店收據複製進草稿。其他裝置改變餘額時保留原輸入，重新核對後清除舊確認，不靜默截低使用者已輸入的實收或退款金額。未知結果固定顯示原款項；重開裝置後接回同一筆待確認紀錄，已保存的原單只核對一次。原草稿完成後才清除，以免下一次收款被舊草稿反覆攔住。

餐點均完成或取消、但訂位仍在用餐中時，未用訂金也屬跨日期待處理事項，不自動標記離席或退款。最後一筆待處理款項結清後，仍可返回原日期。以上本機流程不表示現有安裝檔、對外服務、實機、首次使用者或整套ERP已驗收完成；正式對外收訂金仍須取得相符證據。相關安裝封裝須包含`public/reserve`，本機來源變更不代表安裝檔已更新或服務已部署。
