# 關閉店面與交易保留

2.9.1 修正共用服務啟動與關閉同時發生的衝突，並讓一般關閉視窗與程式結束共用同一個關閉流程。

關閉時先停止接收新的接單／共用店面操作，再等待服務完成啟動或取消啟動，以及連線收尾；兩個服務都停止後才關閉 SQLite。未送完整的請求與 TLS 握手最多保留 1.5 秒收尾時間，然後關閉連線。已提交但沒收到回覆的交易仍保留原單號，重新連線後以原編號核對，不能另開一筆當成重試。

如果服務無法停止，系統保留資料庫並回到畫面，顯示稍後再關閉的提示。共用店面已停止時，手機需等電腦端重新啟動服務、配對與登入。

隔離測試涵蓋實際 SQLite、HTTP／HTTPS 啟停、未送完整的請求、關閉後才送完的有效建單、提交後回覆中斷、重開與原單號重試。`npm run test:shutdown` 執行這些案例；主程式事件順序另由 Vitest 驗證。

**尚未驗收完成：**本機曾觀察到 Electron 原生程序退出延遲，最小引擎程式也有不穩定結果，因此本版不宣稱已達成每次 5 秒內退出。突然斷電、作業系統強制結束、實體手機休眠與實際營業長跑仍需各自驗證。測試通過也不代表完整 ERP 或零 Bug；完整範圍保留在 [產品能力清單](../product-capabilities.json)。
