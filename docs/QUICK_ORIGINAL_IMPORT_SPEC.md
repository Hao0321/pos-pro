# 快速建單：再次匯入已建立的採購

再次貼上同一份採購或報價時，先核對完整原單，再檢查新建單所需的現在價格、對照或效期。找回原單不代表再收貨、付款或修改對照。

## 原單核對

- 使用現在真正登入的管理員、店家及還原世代查詢；原單也必須由同一帳號與角色建立。
- Agent 草稿、公司交換單據及報價，沿用現有穩定編號算法。沒有原回執就走原有的新單檢查，不能用採購摘要猜測成功。
- Agent／一般公司單據，核對已保存採購的供應商、訂購日期、備註、品項順序、商品、單位、數量及明列單價。未明列價格時顯示原採購已保存的約定價，不以現價重算。
- 既有採購回執沒有保存原始 Agent 的 catalogueRevision、草稿時間與公司的完整 SKU 對照。因此此分支證明的是已保存的採購條件，不能宣稱原始 JSON 逐字相同。歷史商品名稱、單位與價格只用來核對既有單據，不能授權新寫入。
- 報價另有完整 sourceQuote，因此連同原始報價修訂、對象與所有欄位一併比對；不同修訂不能默認為已接受。
- 回傳完整且經既有歷史讀取器驗證的原回執，再由畫面重新驗證內容摘要與收據。相同編號卻有不同採購條件時保留輸入，提示核對。

## 畫面與異步

貼上、連結、檔案匯入、重新開啟已有草稿及按確認，都要先核對原單。查詢等待中若切換類型、帳號或世代，舊結果不得結束新草稿。未送出的草稿與已提交的原請求證明分開保存。

## 驗證範圍

以真正原生 IPC、配對 HTTPS 與 browser kernel 量測原價、失去本機送出快取、現價變動、過期、還原與同 ID 異內容。另測沒有原單、權限、偽造回執、兩個視窗及完整帳本不變。這是開發來源變更；正式資安六控制、實體裝置、真人易用性、新安裝檔及全部 ERP 義務仍需各自驗收。
