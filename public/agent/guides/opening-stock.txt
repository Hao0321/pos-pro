# Original inventory / 原庫存搬入
All features are free. This source-only development workflow is not included in the existing 2.16.0 installer.
Discovery: /agent/manifest.json → migrationDraft.openingStock. Source schema: /agent/migration-draft-v1.schema.json. Example: /agent/examples/opening-stock-v1.json.

The Agent prepares source facts only. Return the existing pos-migration-draft/v1 object, with source {system,company}, a stable source batch id and an opening-stock table. Do not generate the application's private opening/master request, actor, scope, review, approval or receipt. Do not log in, fetch URLs, execute code, upload the export, receive goods or move money.

For each opening-stock row preserve its original externalId and string values. Columns: productExternalId, quantity, value, unit, currency, optional cutoffDate and name. quantity has at most three decimal places; value is the actual total inventory carrying value with at most two decimal places. Preserve leading zeroes and the exact original product ID. Unit is the original base unit; no guessed package conversion. Currently the operational cost book is TWD; a currency label supplies no exchange rate. Missing facts stay missing. Blank is not zero.

Optional unitCost is an actual inventory valuation rate, not selling price or a generic reference cost. Up to twelve decimal places are retained, multiplied by the exact quantity and rounded once to cents. If an Agent explicitly supplies both unitCost and value they must agree. In raw reports an authoritative inventory total is used directly; a rounded displayed valuation rate remains original reference data and does not override that total. Formula caches, unsupported number formats and foreign currency require review.

Products, suppliers and customers may accompany stock in the same source draft. New products need a known selling price, name and base unit. Do not make a missing selling price zero. An inventory-only report without selling prices uses permanent source-product mappings established by the owner earlier; missing mappings block confirmation. Exact source system + company + entity + externalId defines identity. Never merge names alone.

Original XLSX/CSV/TSV can go directly through Agent migration in the local app. The owner checks file/source/columns once, then continues into stock review. Strong stock quantity + inventory total/valuation-rate columns identify this path. Only unknown opening cells need a replacement fact; known amounts cannot be rewritten into different numbers. The exact file, selected sheets, physical rows, mappings and corrections remain in the receipt. CSV/TSV <=80000 bytes; XLSX <=120000 bytes; <=5000 source rows. No external AI upload is required by the application.

Owner path: Add file / Paste → Check report date and missing facts → See stock and master trial → Confirm opening inventory. The original report date is the cut-off, not an automatically chosen current date. An optional independently supplied report total can be reconciled with row totals; without it the app does not claim an independent total match. The trial uses the same master and cost-custody projection as the write.

One transaction saves masters, source identities, opening stock, cost sources, the inventory/opening-clearing journal and receipts. It creates no sale, purchase, cash receipt or ordinary stock-surplus transaction. Existing stock/cost history, lot/warehouse/location details and later journals need reconciliation and block this limited opening path. AR/AP, deposits, stored value, points and historical/full-vendor cutover remain unfinished; a stock receipt does not certify the whole migration.

Keep the original operation ID before saving. A lost reply means check the original result; never rename the source to add stock again. A backup from before opening still retains the permanent refusal of already used IDs. Download the opening record and full backup; keep the original system/export. No external Agent write API, arbitrary automatic approval or automatic deletion is offered.
